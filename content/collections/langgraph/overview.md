## 为什么要有图？

简单应用可以线性执行：接收问题、调用模型、返回答案。但任务一旦需要条件分支、回到前一步、保存执行状态，就需要显式表达“下一步做什么”。

LangGraph 用状态和图结构组织执行步骤。这是概念导读，不是当前版本的 API 使用说明；代码示例将在指定依赖版本后单独验证。

## 定义，再看例子

| 概念 | 定义 | 问答任务中的例子 |
| --- | --- | --- |
| State | 在执行过程中传递与更新的数据 | 问题、资料、答案、检查结果 |
| Node | 读取状态并产生更新的处理步骤 | 检索资料、生成答案、检查引用 |
| Edge | 指定步骤之间的后续关系 | 检索完成后进入生成 |
| 条件分支 | 根据结果选择后续步骤 | 引用不足则重新检索，否则结束 |

节点不必都调用模型。检查资料是否为空、控制重试次数等步骤可以由普通程序完成。

## 具体流程

```text
接收问题 → 检索 → 生成 → 检查
               ↑         │
               └─ 资料不足 ┘
                         │
                       通过 → 结束
```

例如第一次检索没有找到“恢复设置”，检查节点可以要求更换关键词，再检索一次。系统需要设置重试上限，避免无休止循环。

## 哪些内容需要分开学习？

- 状态字段怎样定义、怎样合并更新。
- 条件分支与循环怎样控制。
- 检查点与恢复怎样处理。
- 人工介入怎样暂停与继续执行。
- 外部工具产生副作用时，恢复执行怎样避免重复操作。

这里列的是后续专题目录，当前只完成概念导读。图表达了控制流程，不保证每个节点的结果正确，仍需要输入校验、输出验证和真实评测。
