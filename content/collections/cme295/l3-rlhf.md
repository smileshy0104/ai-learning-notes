## 1. RLHF 由哪两步组成？

PDF 第 70–86 页。RLHF = Reinforcement Learning from Human Feedback。经典配方先把人类偏好拟合成奖励模型，再用奖励信号优化生成策略。

<div class="flow"><span class="chip">人类偏好对</span><span class="arrow">→ 训练 →</span><span class="chip">奖励模型 RM</span><span class="arrow">→ 冻结后评价采样 →</span><span class="chip">更新生成模型 Policy</span></div>

**奖励模型与生成模型不是同一个角色。** RM 输出分数，policy 输出 token 概率。两者可能使用相似主干，但训练目标和使用方式不同。

## 2. 奖励模型的输入与输出

```text
输入：(提示 x，完整候选回答 y)
输出：一个实数 rφ(x,y)
```

可以取语言模型某位置的隐藏表示接标量输出层，也可以使用编码器式主干。这个分数不是“事实正确概率”本身，不要求落在0到1，也不是词表分布。

## 3. Bradley–Terry：把分差变成偏好概率

```text
σ(z)=1/(1+exp(−z))
P(y_w ≻ y_l | x)=σ(rφ(x,y_w)−rφ(x,y_l))
L_RM=−E[ln σ(r_w−r_l)]
```

**直觉：** winner 的分数比 loser 越高，模型越相信这个偏好标签，成对负对数损失越低。

例子：r_w=2、r_l=0，分差2，偏好概率约0.8808，损失约0.1269。若两者同分，概率0.5，损失约0.6931。

<!-- lab:l3-preference-gap -->

期望 E 表示对数据中许多偏好对取平均。把所有奖励都加100，分差不变，因此偏好概率不变；没有额外约束时，奖励的绝对零点并不由成对数据唯一决定。

## 4. 为什么奖励不能当真理？

RM 只是在有限标签上学习人的评价规律，可能学到“回答长就更好”“使用某些礼貌词就高分”等捷径。

如果标签本身有分歧、数据覆盖不足，RM 对新任务可能判断错误。验证集应该检查排序质量与各类失效，而不是把训练损失小视为已学到全部价值标准。

## 5. 第二步：优化 policy

policy πθ 通常从 SFT 模型初始化。给它提示，让它采样回答，再用冻结的奖励模型评分。

常见直觉目标（最大化形式）：

```text
J(θ)=E_x E_y~πθ [rφ(x,y)] − β E_x KL(πθ(·|x) || π_ref(·|x))
```

β 控制偏离参考分布的代价。这是说明“高奖励＋不过度偏离”的概念式目标，不是完整 PPO 更新代码。实际还涉及采样、概率比、优势估计、裁剪及可能的 value model，第四讲再深入。

| 对象 | 这一阶段是否更新 | 职责 |
| --- | --- | --- |
| Policy πθ | 是 | 产生更符合目标的回答 |
| Reward model rφ | 经典两阶段中冻结 | 给采样回答评分 |
| Reference π_ref | 通常冻结 | 提供分布约束基准 |
| Value model | 取决于算法 | 估计回报或基线，不是所有方法都有 |

**重要：** 不是把离散生成的字符串直接无条件可导地传过 RM，就能对生成 token 做普通监督反向传播。策略梯度利用 log 概率等构造学习信号，相关细节不能被“评分后反传就行”省略掉。

## 6. KL 在惩罚什么？

KL 衡量两个概率分布差异，并非直接量权重矩阵的欧氏距离。“别改权重太多”是过于粗略的口头直觉。

教学二选一例子：reference=[0.5,0.5]，policy=[0.8,0.2]：

```text
KL=0.8 ln(0.8/0.5)+0.2 ln(0.2/0.5)≈0.1927 nats
```

若两个回答奖励为[1,0]，policy 的期望奖励为0.8；β=0.5 时简化目标 `0.8−0.5×0.1927≈0.7036`。增加奖励需要与偏离代价权衡，不是永远越接近 reference 越好。

## 7. Reward hacking：高分不等于好答案

模型可能找到奖励模型偏爱的形式，却绕过真实任务。例如长篇重复得到高分，但没有回答用户问题。KL 约束能抑制某些过度偏移，**不能保证消除奖励漏洞**。

应配合独立任务评测、人工抽检、奖励数据维护与约束检查。模型越擅长优化错误代理目标，问题可能越明显。
