## 1. 什么是缩放法则？

对应 PDF 第 22–34 页。缩放法则是实验中观察到的规律：在特定模型、数据和训练设定下，测试损失怎样随模型参数 N、训练 token 数 D 和计算量 C 变化。

常见直觉式表达是 `L ≈ 不可约损失 + A/N^α + B/D^β`。这是教学概括，不是本课程对所有模型宣布一个唯一公式。指数与常数需要由具体实验拟合。

**为什么需要**：训练大模型很贵，不能把每种规模都完整试一遍。小规模实验可以为大规模资源规划提供参考。

## 2. 更多参数、更多数据，各自解决什么？

| 因素 | 直觉 | 不能推导出的结论 |
| --- | --- | --- |
| 参数量 N | 增加可学习容量 | 每个任务都会变好 |
| 数据量 D | 更多训练信号与覆盖 | 垃圾数据也与高质量数据等价 |
| 计算量 C | 允许更多或更大的训练步骤 | 同样 FLOPs 的方案效果必然相同 |

课件第 24 页强调较大模型在相应实验中更有**token 效率**：达到某一损失所需的训练 token 更少。但一个 token 的计算变贵了，所以这不等于算力或能源更省。

例子：小模型需要 1000 个示例，大模型需要 600 个示例达到目标。如果大模型每个示例计算为小模型的 3 倍，总量是 1800 对 1000；样本更省，计算却更多。数字只演示概念。

## 3. FLOPs 与 FLOP/s，差一个时间单位

- FLOPs：浮点运算总次数，像路程。
- FLOP/s（也写 FLOPS）：每秒能做多少次运算，像速度。
- 时间的理想估计：总运算次数 ÷ 每秒运算次数。

```text
总计算量 = 1.2×10¹⁸ FLOPs
有效计算速率 = 2×10¹⁴ FLOP/s
理想时间 = 6000 秒 ≈ 1.67 小时
```

有效速率不是 GPU 宣传的峰值。数据读取、通信、内存和利用率都影响实际时间。字幕“训练失败次数”是 FLOPs 的误译。

## 4. 固定预算下，N 与 D 不能同时无限大

**补充近似**：稠密 Transformer 的训练主计算有时用 `C ≈ 6ND` 估算。它忽略部分注意力、嵌入和系统成本，长序列或特殊结构下偏差会变大。

例如给定 `C = 1.2×10²⁰ FLOPs`：

| 模型参数 N | 由 C≈6ND 算出的 D |
| --- | --- |
| 1×10⁹（1B） | 2×10¹⁰（20B tokens） |
| 2×10⁹（2B） | 1×10¹⁰（10B tokens） |
| 4×10⁹（4B） | 5×10⁹（5B tokens） |

三个方案预算近似相同，但大模型看到的数据更少。真正最优点需要损失实验，不是从乘法表直接选最大 N。

## 5. Chinchilla：模型与数据要配套

课件第 27–28 页介绍 Hoffmann 等 2022 年的计算最优训练研究，给出著名量级直觉：**约 20 个训练 token 对应一个参数**。

```text
D ≈ 20N
70B 参数 × 20 ≈ 1.4T 训练 tokens
```

训练 token 数是训练中处理的数量，需要说明重复与数据口径；不一定等同于独立语料的去重规模。

课件比较更小、数据更多的 Chinchilla 与更大、数据更少的 Gopher，强调当时许多大模型在给定训练预算下“参数太大、训练不足”。

**边界**：20:1 是特定研究背景下的经验结果，不是所有模型的硬规则。长时间服务大量请求时，部署者可能更愿意训练一个更小但训练更充分的模型，以降低长期推理成本。

## 6. 什么叫“大语言模型”？

语言模型给 token 序列分配概率。课程用参数、数据与计算都很大的模型介绍 LLM，并聚焦 decoder-only Transformer。

“大”没有统一精确的参数门槛；LLM 与 decoder-only 并非逻辑同义词。MoE 的总参数和激活参数也要分开，详见[专家路由](l2-moe.html)。
