## 1. 从预测到选择，还差一步

对应 PDF 第 89–123 页。模型把隐藏表示投影成词表 logits，再经 softmax 得到概率；**解码策略决定如何利用概率选择下一个 token**。

```text
上下文 → 网络 → logits z → 概率 p → 选择 token → 追加到上下文 → 重复
```

这与训练时最小化交叉熵不同：推理时不是对下一词标签反向训练，而是在固定模型下做选择。

## 2. 贪心：每次挑当前最高概率

Greedy decoding 选择 `argmax p`。优点是简单；缺点是当前最佳一步不等于整条序列概率最高。

### 两步完整反例

第一步 A 的概率 0.6、B 为 0.4。第二步条件分布：

| 前缀 | 下个 X | 下个 Y | 对应最高两步联合概率 |
| --- | --- | --- | --- |
| A | 0.51 | 0.49 | P(AX)=0.6×0.51=0.306 |
| B | 0.99 | 0.01 | P(BX)=0.4×0.99=0.396 |

贪心先选 A，再选 X，得到 AX；但 BX 更可能。每行概率都加到 1。这个例子固定两步结束，不涉及不同长度比较。

## 3. Beam search：保留多个前缀

Beam width=2：先保留 A 和 B，再扩展四条候选：

```text
AX: 0.306    AY: 0.294
BX: 0.396    BY: 0.004
保留 BX 与 AX
```

通常以对数概率相加计算，避免长序列乘积下溢。实际搜索还要处理 `[EOS]`、长度惩罚和终止条件。

Beam 是受限搜索，不保证全局最优；不同长度概率也不能天真比较。更大的 beam 可能更慢，且最高似然不等于最有用、最真实或最有创意的回答。

## 4. 采样：按概率抽取，不总取第一名

若候选分布 `[0.40,0.25,0.20,0.10,0.05]`，第一名长期平均约被选 40%，不是每次都选它。真实单次抽样可能选到任何非零候选。

随机性适合需要多样性的任务；对可重复抽取、评测等任务可以偏好确定性策略。不存在“所有场景随机一定更好”。

## 5. Top-k 与 Top-p

### Top-k：固定保留几个

k=2，保留前两名，总概率 0.65，重新归一化：

```text
[0.40/0.65, 0.25/0.65] ≈ [0.6154,0.3846]
```

然后从这两个候选中抽样。Top-k 不是强制每 k 步换一个词。

### Top-p：固定保留多少概率质量

按概率从大到小，取累计概率**第一次达到或超过阈值**的最小前缀，再归一化。

| p 阈值 | 保留原概率 | 原质量 | 新分布 |
| --- | --- | --- | --- |
| 0.60 | [0.40,0.25] | 0.65 | [0.6154,0.3846] |
| 0.80 | [0.40,0.25,0.20] | 0.85 | [0.4706,0.2941,0.2353] |
| 0.90 | [0.40,0.25,0.20,0.10] | 0.95 | [0.4211,0.2632,0.2105,0.1053] |

p=0.8 不意味着只保留原概率小于 0.8 的词，也不保证留下固定个数。Top-k 与 Top-p 同时使用时，顺序与实现约定需要查具体服务。

## 6. 温度：调分布形状

```text
pᵢ(T) = exp(zᵢ/T) / Σⱼ exp(zⱼ/T)，T>0
```

- 低 T：更尖，偏向高分候选。
- T=1：原 softmax。
- 高 T：更平，较低分候选更容易出现。

<!-- lab:temperature -->

<strong>重要：</strong>任何有限正温度下，如果仍做采样，就不是严格的贪心。T=0 时公式除零没有定义，API 中的 `temperature=0` 通常是约定进入贪心或近似确定性模式。T→0⁺ 在最大分唯一时集中到最大项；若并列还要看 tie-break 规则。

Temperature 改变相对概率，Top-k / Top-p 截断候选。它们改变输出，不会把权重重新训练，也不保证更低温度回答更真实。

## 7. 为什么温度为零仍可能不完全复现？

PDF 第 115–116 页讨论服务中的非确定性。权重、输入和理论运算固定，不代表每个硬件和批处理配置的浮点路径完全一致。

```text
(10¹⁶ + (−10¹⁶)) + 1 = 1
10¹⁶ + ((−10¹⁶) + 1) = 0  （常见 IEEE 754 双精度下）
```

浮点加法不严格满足结合律。内核、批处理、规约顺序和数值精度的微小差异，可能在候选分数非常接近时改变 argmax。还要固定模型版本、提示模板、工具结果、种子与运行环境，不能只设 T=0 就声称绝对复现。

## 8. Guided decoding：限制哪些下一 token 合法

**定义：**生成过程中用语法或 Schema 检查当前前缀，只允许合法续写。可以把不合法候选分数设为 −∞，再在合法集合中归一化与选择。

例如目标是 `{"age":33}`：

```text
当前前缀：{"age":
若 Schema 要求 age 为整数，下一步不能继续一个普通对象键
合法续写需要组成一个整数，然后闭合对象
```

这些是字符级直觉示意。实际 token 可能包含多个字符，约束实现需要处理 token 到语法状态的转换，不能把一个 token 永远当作一个字符。

<div class="flow"><span class="chip">模型 logits</span><span class="arrow">＋ 语法状态 →</span><span class="chip">屏蔽不合法候选</span><span class="arrow">→ 选择 →</span><span class="chip">更新语法状态</span></div>

**格式合法不等于事实正确。**符合 Schema 的 age 仍可能是编造的；还需要字段校验、来源核对与业务验证。截断、拒答和服务支持范围也可能造成生成失败，不能简单承诺任何情况下 100% 成功。
