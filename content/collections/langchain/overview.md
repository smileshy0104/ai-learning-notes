## 这个专题解决什么问题？

当一个应用需要调用模型、拼接消息、读取外部资料、执行工具时，可以通过组件接口把这些步骤组织起来。LangChain 提供了一组围绕模型应用的组件与集成。

这篇是概念导读，**尚未提供绑定具体版本的 API 教程**。后续代码文章会注明语言、包版本、运行环境与验证结果。

## 一个具体任务：根据产品手册回答问题

假设用户问：“这个产品怎样恢复出厂设置？”

1. 应用接收用户问题。
2. 检索组件从产品手册找出相关段落。
3. 应用把问题和段落组织成消息发送给模型。
4. 模型根据提供的资料生成回答。
5. 应用检查回答是否有来源，并呈现给用户。

这里的模型生成、资料检索、消息组织是不同职责。采用框架不意味着自动获得可靠答案，检索质量与输出验证仍需分别评估。

## 先区分四个概念

| 概念 | 职责 | 本例中 |
| --- | --- | --- |
| 消息 | 表达角色与内容 | 用户问题、系统要求、检索资料 |
| 模型 | 根据消息产生输出 | 生成恢复设置的说明 |
| 检索器 | 根据查询找资料 | 找出手册中相关段落 |
| 工具 | 提供可调用的外部操作 | 查询产品型号或工单状态 |

检索器不是模型记忆本身；工具调用也不是模型直接执行程序，实际执行由外部系统完成。
