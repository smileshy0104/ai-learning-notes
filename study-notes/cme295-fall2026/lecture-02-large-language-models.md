## 第二讲导读：从 Transformer 到 LLM

### 这一页写给谁

如果你第一次接触大语言模型（Large Language Model，LLM），读课件时最常见的反应是：“每个字都认识，连起来不知道在讲什么。”这不是你的问题，而是课件默认你已经知道一些背景。这一讲共 138 页，讲义里频繁出现 token、embedding、attention、router、cache、logits 这些词，中间不会停下来解释。

这一页要做三件事：先用一个句子把整讲的流程走一遍；再补齐四个真正需要的前置概念；最后告诉你每一节该带着什么问题去读，以及第一遍可以跳过什么。

你不需要会微积分、线性代数或训练模型。会用纸笔做乘法，能接受“把一串数字当成一个整体来看”，就足够开始。

### 一个句子的完整旅程

设想你在输入框里只写了这一句，然后让模型接着写：

```text
A cute teddy bear is
```

下面这六步就是大语言模型回答任何问题的基本流程。每一步只回答一个问题：<strong>此刻数据变成了什么样子？</strong>

1. <strong>切分</strong>：文字被切成词元（token）。教学例子里，假设每个英文单词恰好是一个 token，于是得到 5 个 token。真实分词器会切出子词，这里是刻意简化。
2. <strong>查表变数字</strong>：每个 token 有一个编号，模型按编号从一张大表里取出一行数字，这叫嵌入向量（embedding）。文字从此变成数字，后面的所有运算都只处理数字。
3. <strong>加入顺序信息</strong>：光有数字，模型不知道谁在前谁在后。位置机制（例如旋转位置编码 RoPE）把“这是第几个字”编码进这些数字里。
4. <strong>让位置之间互相看</strong>：自注意力（self-attention）让最后一个位置去读取前面 `teddy`、`bear` 等位置的信息；前馈网络（feed-forward network，FFN）再逐个位置加工。这组操作重复多层，表示越往下越“懂上下文”。
5. <strong>打分</strong>：最后一层把结果投影成词表上每个候选的分数，这个分数叫 logit。softmax 把分数变成总和为 1 的概率，例如 `reading` 得 0.6、`sleeping` 得 0.4。
6. <strong>选择并回填</strong>：解码策略（decoding strategy）从这份概率里选一个词，比如选中 `reading`。把它接到句子末尾，下一轮的输入就变成 `A cute teddy bear is reading`，然后重复第 1 到第 6 步，直到写出结束符。

这套“选一个、接回去、再选一个”的写法叫自回归生成（autoregressive generation）。它不是被特别设计出来的花样，而是第 6 步的自然结果：模型的输入和输出是同一串 token。

| 你会反复遇到的词 | 一句白话 | 本讲在哪展开 |
| --- | --- | --- |
| token（词元） | 模型读写的最小单位 | 第一讲回顾 |
| embedding（嵌入向量） | 把一个 token 变成一串数字 | 第一讲回顾 |
| attention（注意力） | 让一个位置去别的位置找信息 | 位置与注意力效率 |
| logit | 还没变成概率的原始分数 | 解码策略 |
| softmax | 把一组分数压成概率 | 解码策略 |
| 参数（parameter） | 训练中被反复调整的那些数字 | 缩放法则 |

关键区分：第 1 到第 5 步是<strong>模型算出来的</strong>，第 6 步是<strong>策略选出来的</strong>。模型给 `reading` 0.6、`sleeping` 0.4，这个分布不会因为换了解码策略而改变；改变的是你从这份分布里挑哪个词。很多初学者的困惑——“为什么同一个问题答案不一样”——就出在第 6 步。

### 四个必须先会的小工具

这四个概念在后面每一节都会用到。每个都给一个能手算的例子，先看懂“它在做什么”，不必背公式。

#### 工具一：向量就是一串数字

`[0.2, -0.5, 0.9]` 是一个三维向量，也就是“三个数字排成一队”。一个 token 的 embedding 可能是几千维，道理完全相同，只是数字更多。

模型的所有中间结果——每个 token 在每一层的状态——都是这样的向量。看到“把 x 送进某个层”，就是“把这一队数字送进一个函数”。

#### 工具二：点积衡量“有多像”

两个向量对应位置相乘再相加，叫点积（dot product）：

```text
[1, 2, 3] · [0, 1, 0] = 1×0 + 2×1 + 3×0 = 2
```

注意力里的“匹配分数”就是点积。两个向量的方向越一致，点积越大，说明这个位置提供的信息越贴近当前位置想要找的东西。位置编码、缓存、归一化都会用到这里。

#### 工具三：softmax 把分数变成概率

给定分数 `2.0` 和 `1.0`，先各自取指数，再除以总和：

```text
exp(2.0) ≈ 7.389，exp(1.0) ≈ 2.718
总和 ≈ 10.107
概率 ≈ [0.731, 0.269]
```

分数大的一方拿到更大的概率，但小的一方也不会变成 0。这就是为什么模型总能“说出别的词”，也是温度（temperature）能调节输出风格的根源。

#### 工具四：多层堆叠与残差

一层处理完，结果交给下一层。为了让深层网络好训练，每一层还会把输入直接加到输出上，这条直通路径叫残差连接（residual connection）。归一化（normalization）则负责把数值控制在合适范围内。

所以“第 12 层看到的信息”和“第 1 层看到的信息”不是一回事。后面讲滑动窗口和感受野时，这个直觉很关键。

### 新手常卡住的三个问题

下面三个问题几乎每个初学者都会问一遍，先看答案，读到对应章节时会更顺。

<details><summary>“模型是在理解语言，还是只是在算概率？”</summary><p>它在做条件概率预测：给定前面的 token，给下一个 token 分配概率。至于这种预测为什么表现出“理解”的效果，是目前仍在研究的问题。学习这一讲时，先接受这个操作定义，不要把“概率高”直接等同于“说得对”。</p></details>

<details><summary>“参数、训练、推理到底谁改谁？”</summary><p>参数是模型里那些数字。训练是用数据反复调整参数；推理是参数冻结后，用模型回答问题。你日常使用聊天模型时，几乎总是在推理，参数不会因为一次对话而改变。这也是后面区分“上下文学习”“微调”“提示”的基础。</p></details>

<details><summary>“为什么课件里的公式看起来比解释难那么多？”</summary><p>公式通常只是把一段自然语言压缩成符号。例如注意力分数就是“查询和键做点积再缩放”，公式里每个符号都对应一句话。本讲的每篇笔记都会先讲这句话，再给出公式；第一遍读不懂矩阵，就先读那句话。</p></details>

### 第一遍怎么读

按上表的顺序读，但<strong>第一遍的目标不是全部算明白，而是知道每一节在解决什么问题</strong>。建议这样分配注意力：

- 解码与提示：随时问自己“这一步改的是模型看到的文字，还是从候选里选词的方法”。

### 读完能做什么

- 说清一次生成中，哪一步是模型算的、哪一步是策略选的。
- 解释三类架构（encoder-only、decoder-only、encoder–decoder）在可见范围上的差别。
- 区分参数量、训练 token 数和计算量，说明它们为什么会互相牵制。
- 说清 MoE 中“总参数”和“每个 token 激活参数”为什么不同。
- 解释 RoPE 为什么能让注意力感知相对位置。
- 说明 GQA 为什么能节省缓存，以及省下来的到底是什么。
- 区分“格式合法”“算得对”“信息找得准”这三件事。

## 模型家族：BERT、GPT 与三类架构

### 1. 先破除一个误解

很多初学者听到 BERT 和 GPT，第一反应是背名字和年份。其实这一节只回答一个问题：

<strong>同一个 Transformer 架构，删掉一部分之后，还能做什么？</strong>

回忆第一讲：原始 Transformer 是为机器翻译设计的，左边编码器读源句，右边解码器写译文。课件第 6 页把这两个角色重新摆出来，然后问：如果我只想“读懂一句话”，还需要会写字的那一半吗？如果我只想“接着往下写”，还需要一个专门读输入的半边吗？

两个问题对应两种删法，答案就是 BERT 和 GPT。

### 2. 编码器与解码器到底在做什么

用一句话理解：

- <strong>编码器（encoder）</strong> 的任务是“把输入整理成表示”：所有位置可以同时互相看，每个位置都得到一个融合了整句信息的向量。
- <strong>解码器（decoder）</strong> 的任务是“一个接一个地写”：第 t 个位置只能看自己和它前面已经写出的内容，用它来预测第 t+1 个。

差别不在参数多少，而在<strong>一个位置允许看见哪些位置</strong>。这个允许范围叫可见范围，实现方式是注意力掩码（attention mask）。

| 家族 | 一个位置能看见 | 典型输出 | 代表 |
| --- | --- | --- | --- |
| 只看编码器（encoder-only） | 左边和右边（双向） | 每个位置的上下文向量，再接任务层 | BERT |
| 只看解码器（decoder-only） | 自己和左边（因果） | 下一个 token 的概率 | GPT 类 |
| 编码器＋解码器 | 编码器双向；解码器因果，并能读编码器输出 | 目标序列逐步生成 | 原始 Transformer、T5 |

请注意第三列和第四列。它们不是“谁更聪明”的排名：生成模型也可以做分类，标准 BERT 也能被改造成生成模型。真正的区别是训练目标、可见范围和对外接口。

### 3. 同一句话，两道题

把这句话写在纸上：

```text
A cute teddy bear is reading
```

#### 第一道题：填空

遮住中间一个词：

```text
A [MASK] teddy bear is reading
```

你填补 `cute` 时，既看了左边的 `A`，也看了右边的 `teddy`、`bear`。BERT 的训练就是这样：故意破坏一些位置，让模型用两侧信息还原。这解释了它为什么叫<strong>双向（bidirectional）</strong>。

#### 第二道题：续写

只留下前半句：

```text
A cute teddy bear is
```

这时你要猜下一个词。注意：训练 GPT 时，即使原句里有 `reading`，模型也必须看不见这个答案，否则就是抄答案。这条“只能看左边”的规则叫<strong>因果掩码（causal mask）</strong>。

来看因果掩码具体长什么样。设四个位置 `[BOS] A cute teddy`，行是“谁在看”，列是“能看到谁”，✓ 表示允许：

| 查询位置 | BOS | A | cute | teddy |
| --- | --- | --- | --- | --- |
| BOS | ✓ | ✗ | ✗ | ✗ |
| A | ✓ | ✓ | ✗ | ✗ |
| cute | ✓ | ✓ | ✓ | ✗ |
| teddy | ✓ | ✓ | ✓ | ✓ |

这个下三角形状就是 decoder-only 的核心约束。它保证训练时可以一次并行算出所有位置的预测，但每个位置的信息都不会来自未来。

### 4. BERT：先把语言读懂，再接任务

BERT = Bidirectional Encoder Representations from Transformers，出自 2018 年论文，课件在第 7–12 页介绍。

它保留 Transformer 的编码器，丢掉解码器，于是每个位置都能双向读取。为了让整句有一个可用于分类的位置，输入开头加一个特殊符号 `[CLS]`，句子之间用 `[SEP]` 分隔。

<strong>为什么需要双向？</strong> 以“bank”为例：在“river bank”里是河岸，在“bank account”里是银行。如果只看左边，判断会差很多；双向编码让每个位置的表示都吸收了整句语境。

一个分类任务的流程：

```text
[CLS] 这只熊 很 可爱 [SEP]
   → 编码器（双向注意力）
   → 每个位置一个上下文向量
   → 取 [CLS] 的向量，接一个分类层
   → 正面 / 负面
```

`[CLS]` 本身没有任何神奇含义。它之所以能代表整句，是因为训练时它的向量被要求去预测某些东西（例如下一句是否相邻），从而被迫汇总全句信息。序列标注任务则不必用 `[CLS]`，直接用每个位置的向量即可。

### 5. BERT 怎么训练：两个代理任务

训练分两步。第一步叫预训练（pretraining），用海量无标注文本，靠“代理任务”让模型学语言规律；第二步叫微调（fine-tuning），用少量带标签数据，把模型调到具体任务上。

代理任务的意思是：它本身不是你真正想解决的问题，只是借它来学到有用的表示。

#### 代理任务一：掩码语言模型（MLM）

从输入中随机挑一些位置破坏掉，让模型还原原词。

```text
原句：[CLS] A cute teddy bear is reading [SEP]
输入：[CLS] A [MASK] teddy bear is [MASK] [SEP]
目标：           cute                   reading
```

只看被破坏的位置算损失。假设模型给 `cute` 的概率是 0.6，给 `reading` 的概率是 0.5：

```text
L = [−ln(0.6) − ln(0.5)] / 2
  ≈ [0.5108 + 0.6931] / 2
  ≈ 0.602
```

损失越小，说明模型给正确答案的概率越高。这个数字本身没有绝对意义，它的作用是让训练过程有个可优化的目标。

原论文的细节（课件只做了概括）：被选中做预测的位置约占 15%；在这些位置中，约 80% 替换成 `[MASK]`，10% 换成随机词，10% 保持原样。为什么不全用 `[MASK]`？因为真实使用中根本不会出现 `[MASK]`，全用它会让训练和实际输入差距太大。

#### 代理任务二：下一句预测（NSP）

给模型两个句子，判断第二句是不是原文中紧跟第一句的那句。

| 输入句对 | 目标 |
| --- | --- |
| A：我拿出一本书。B：然后开始阅读。 | 相邻 |
| A：我拿出一本书。B：火星是太阳系行星。 | 随机配对 |

这样做的目的是让模型学文档级的连贯性，而不只是句子内部。注意标签来自数据构造方式，不是让模型判断“读起来通不通顺”。后续很多 BERT 变体已经放弃 NSP，所以它不是编码器的必备组件。

### 6. 预训练与微调，分别改了什么

| 阶段 | 数据 | 改什么 | 成本 |
| --- | --- | --- | --- |
| 预训练 | 海量无标注文本 | 几乎全部参数 | 很高，通常只做一次 |
| 微调 | 任务数据（如带标签评论） | 输出层，常常还有编码器参数 | 低得多，每个任务做一次 |
| 特征提取 | 任务数据 | 只训练输出层，编码器冻结 | 最低，但要接受表示不够贴合任务 |

一个容易误解的点：微调“通常不需要很多数据”是相对预训练而言的，不是说几百条就必然够。数据质量、任务难度、与预训练分布的差距都会影响结果。

### 7. GPT：把所有任务写成“猜下一个词”

GPT = Generative Pre-trained Transformer，同样出自 2018 年，课件在第 13–21 页。

它只保留解码器，并把原始解码器里“读取编码器输出”的交叉注意力也去掉，于是主干非常干净：因果自注意力加前馈网络，一层层堆叠。

训练方式是标准的下一词预测，把目标整体错开一位：

| 输入位置 | 预测目标 |
| --- | --- |
| [BOS] | A |
| A | cute |
| cute | teddy |
| teddy | bear |
| bear | is |
| is | reading |

整句概率按链式法则相乘：

```text
P(A, cute, teddy, bear, is, reading)
= P(A|[BOS]) × P(cute|A) × … × P(reading|A cute teddy bear is)
```

这套写法最大的好处是“同一个模型可以干任何事”：分类也可以写成生成。

```text
判断情感：这只熊真可爱。情感是：
→ 模型续写：正面
```

这里有个重要的边界：<strong>“不用为每个任务重新训练”是使用上的便利，不等于每个 GPT 模型开箱就能听懂指令。</strong> 早期基座模型需要提示工程甚至微调才能稳定完成任务，这一点后面提示与推理一节还会讲。

### 8. 既然都能写，为什么 decoder-only 赢了

两种架构都能生成文本，区别在输入怎么处理：

| 问题 | 编码器＋解码器 | 只用解码器 |
| --- | --- | --- |
| 输入怎么进模型 | 先编码成一套向量，再让解码器交叉读取 | 和输出拼在同一条序列里 |
| 输入内部的注意力 | 双向，任意两个位置都能互看 | 因果，只看自己和左边 |
| 是否要为输入单独设计处理 | 是 | 否，一视同仁 |
| 适合的任务 | 输入输出界限清楚，如翻译 | 开放式生成、对话、统一文本接口 |
| 主要代价 | 结构更复杂，多一套编码计算 | 提示本身也受因果约束，长提示计算量大 |

课件里的结论是：两种范式都试过，但最终绝大多数人选择 decoder-only，原因不是它在所有任务上都更准，而是它更简单——不需要为输入单独设计一条处理路径，任何任务都可以包装成“给一段文字，接着写”。

### 9. 第一遍读到这里，应该能回答

<details><summary>去掉编码器，原来的交叉注意力怎么办？</summary><p>标准 decoder-only 把交叉注意力整块去掉，只保留因果自注意力和前馈网络等组件。它不是把编码器输出设为零，而是根本不存在这条输入路径。</p></details>
<details><summary>MLM 和下一词预测，最本质的差别是什么？</summary><p>预测位置能看到什么。MLM 的预测位置可以看左右两侧；因果语言模型的预测位置只能看左侧。这直接导致输入构造方式和损失计算位置不同。</p></details>
<details><summary>为什么 BERT 要用 [CLS]？</summary><p>为了给句子级任务一个固定的汇总位置。它的汇总能力来自训练，不是符号本身自带的。</p></details>

### 10. 容易记混的地方

- <strong>BERT 不是“只能做分类”</strong>：它输出的是每个位置的上下文表示，表示可以用来做很多任务。
- <strong>GPT 不是“只能生成”</strong>：分类也可以写成生成，只是输出形式不同。
- <strong>NSP 不是必需组件</strong>：它只是经典 BERT 的一个训练目标。
- <strong>decoder-only 流行不等于其他架构消失</strong>：T5、编码器类检索模型仍在大量使用。
- <strong>`[MASK]` 只在训练中出现</strong>：推理时没有这个符号，这是 MLM 与真实输入之间的天然差距。

来源：PDF 第 6–21 页及对应字幕。MLM 的 15% 与 80/10/10 来自原论文背景补充；损失数值、因果掩码表格与情感例子为教学构造。


## 缩放法则：参数、数据与计算预算

### 1. 这一节想解决什么现实问题

对应 PDF 第 22–34 页。

假设你有一笔固定的训练预算，能租到的 GPU 数量和运行时间是确定的。你要做决定：

- 训练一个 70,000,000,000（700 亿）参数的模型，让它读 1,000,000,000,000 个 token？
- 还是训练一个 20,000,000,000（200 亿）参数的模型，让它读 10,000,000,000,000 个 token？

这两个方案花的计算量差不多，但效果可能差很多。缩放法则（scaling law）就是用实验总结出的规律，帮你在动手前估算“哪个方案更划算”。

课件第 23–26 页展示的是 2020 年 Kaplan 等人的观察：模型越大、训练 token 越多、计算越多，测试损失越低，而且规律相当平滑。第 27–28 页则是 2022 年 Chinchilla 的修正：<strong>不是越大越好，而是参数和数据要配套。</strong>

### 2. 先认清三个量，别把它们混成一个“大”

初学者最容易把下面三件事当成同一个“模型规模”。它们其实不同，而且会互相牵制。

| 名称 | 符号 | 是什么 | 比喻 |
| --- | --- | --- | --- |
| 参数量 | N | 模型里可学习的数字有多少 | 学生大脑的容量 |
| 训练 token 数 | D | 训练时一共读了多少 token | 一共做了多少道题 |
| 计算量 | C | 训练实际做了多少次浮点运算 | 学习总工时 |

“模型更大效果更好”这句话必须补条件：<strong>在什么数据、多少预算、哪项评测上。</strong> 否则它没有可操作含义。

还需要知道一个单位细节。

- <strong>FLOPs</strong>：浮点运算的<strong>总量</strong>，像路程，单位是“次”。
- <strong>FLOP/s</strong>：每秒能做多少次浮点运算，是<strong>速度</strong>，描述硬件性能。

课件字幕里“训练失败次数”是 FLOPs 的误听。大语言模型训练常在 10²⁵ FLOPs 量级，而一块 GPU 可能标称 10¹⁴ 到 10¹⁵ FLOP/s。把两者搞混，会算出一台机器几秒钟训完一个模型的荒谬结论。

### 3. 为什么增加参数和增加数据都能降损失

#### 参数多，容量大

参数可以理解为模型内部可以调节的“旋钮”。旋钮多，模型能表达的规律更复杂。但只有旋钮没有数据，它也调不出正确位置，就像买了一套高级画具却没见过画。

#### 数据多，见过的模式多

更多 token 意味着更多语言现象、更多搭配、更多长尾情况。但数据多而模型小，容量会成为瓶颈，学不完。

#### 两者相互制约

这就是缩放法则的核心图像：损失随 N 增加而下降，随 D 增加也下降，但每多一倍的收益在递减。课件第 24 页还指出一个常被忽略的事实：<strong>在相同损失目标下，大模型需要的 token 更少</strong>，这叫更高的 token 效率。但这不代表总计算更省——每个 token 的处理变贵了。

一个教学算例：

```text
小模型：需要 1000 个示例达到目标损失，每示例成本 1 单位 → 总成本 1000
大模型：需要 600 个示例达到目标损失，每示例成本 3 单位 → 总成本 1800
```

样本更省，算力更贵。这就是为什么不能只听“大模型更高效”这半句话。

### 4. 固定预算下的手算练习

一个常用的粗略估算（适用于稠密 Transformer 训练的主要计算）：

```text
C ≈ 6 × N × D
```

为什么是 6？粗略地说，前向传播每个参数约 2 次运算（乘加），反向传播约 4 次，加起来约 6 次。这个式子忽略了注意力随序列长度的增长、嵌入层和通信开销，所以只是量级估算。

现在给定预算 `C = 1.2×10²⁰ FLOPs`，我们看看不同 N 下能读多少 D：

| 参数量 N | 用 C≈6ND 解出的 D | 直观看 |
| --- | --- | --- |
| 1×10⁹（1B） | 2×10¹⁰（20B token） | 小模型，读得多 |
| 2×10⁹（2B） | 1×10¹⁰（10B token） | 翻倍参数，数据减半 |
| 4×10⁹（4B） | 5×10⁹（5B token） | 继续翻倍，数据再减半 |

把指数写成十进制更容易体会量级：`2×10¹⁰` 是 200 亿个 token，`5×10⁹` 是 50 亿个。

把这些量级和日常长度对上：一页课文约 500 个 token，2000 个 token 大约四页，10 万个 token 接近一本小书。而 50 亿与 100 亿这样的数目已经是训练规模，不是一次阅读的规模。

<strong>自己动手算一遍第一行</strong>：

```text
C = 1.2×10²⁰
D = C / (6N) = 1.2×10²⁰ / (6 × 1×10⁹)
  = 1.2×10²⁰ / 6×10⁹
  = 2×10¹⁰
```

也就是说，在预算固定时，参数翻倍就要让数据减半，否则超支。<strong>但注意：这张表只告诉你预算怎么花，没告诉你哪种花法效果更好。</strong> 哪一行最优，必须靠小规模实验测损失曲线，这正是下一节 Chinchilla 要回答的事。

### 5. Chinchilla：20 个 token 配 1 个参数

课件第 27–28 页介绍 Hoffmann 等 2022 年的工作。他们用大量不同 N、D 组合的实验，拟合成一个经验关系，得出一个广为引用的量级直觉：

<strong>约 20 个训练 token 对应 1 个参数。</strong>

```text
70B 参数 × 20 ≈ 1.4T 训练 token
```

这个数字之所以有名，是因为它推翻了之前的做法。课件用两个模型对比：同样计算预算下，一个参数更多、数据更少（类似 Gopher），一个参数更少、数据更多（Chinchilla），结果后者损失更低。结论是当时很多大模型“参数太大、训练不足”，也就是欠训练（undertrained）。

几个必须说明的边界：

- 20:1 是在他们的实验设置下拟合出来的，不是物理定律。
- 训练 token 数是“处理过的 token 数量”，重复数据也算，不等于去重后的语料规模。
- 推理成本是另一回事。如果你要长期服务海量请求，可能反而希望模型更小、训练更充分，因为推理是按请求持续付费的。

课件字幕里提到“一个 700 亿和一个 2000 多亿”的对比，参数数字以课件为准；这里只保留可核对的数量级关系。

### 6. 实际做决定时的三张账单

| 账单 | 受什么影响 | 什么时候占主导 |
| --- | --- | --- |
| 训练计算 | C ≈ 6ND | 一次性投入，通常最贵 |
| 训练显存与通信 | 参数量、并行策略、批大小 | 决定你能不能训得动 |
| 推理成本 | 模型大小 × 请求数 × 序列长度 | 上线后长期付费 |

Chinchilla 优化的是第一张账单在固定预算下的效果。真实工程还要看后两张：一个训练最优的模型，如果太大导致每次请求都贵，也未必是商业上最优。

### 7. 什么叫“大语言模型”

语言模型的本质是：给一段 token 序列分配概率，也就是预测下一个 token。所谓“大”，通常指参数、训练数据、计算三方面都很大，并且现在基本都基于只看解码器的 Transformer。

需要提醒两点：

- “大”没有统一门槛，不同时期的标准不同。
- LLM 与 decoder-only 不是同义词。MoE 模型的总参数与激活参数也要分开看，见[专家路由](../../content/collections/cme295/l2-moe.md)。

### 8. 理解检查

<details><summary>用 C≈6ND 估算：如果 N 从 1B 增到 3B，预算不变，D 变成原来的多少？</summary><p>D = C/(6N)，N 变为 3 倍，D 就变为 1/3。这只是同一估算式下的直接结果，不代表 1B 方案效果更好或更差。</p></details>
<details><summary>“大模型 token 效率更高”能不能推出“训练更省钱”？</summary><p>不能。token 效率说的是达到同样损失需要更少 token；省钱还要看每个 token 的计算成本。例子中样本从 1000 降到 600，但单价从 1 涨到 3，总成本反而升高。</p></details>
<details><summary>为什么 20:1 不能直接套到所有模型上？</summary><p>它依赖具体结构、数据分布和训练设定。换成 MoE、不同序列长度或不同数据质量，拟合关系会变。课件问答里也建议先做小规模实验确认自己设置下的规律。</p></details>

来源：PDF 第 22–34 页及对应字幕；Kaplan 等 2020、Hoffmann 等 2022。6ND 估算、预算表、成本算例为教学补充，数值已用脚本复核。


## MoE：每个 Token 选择哪些专家？

### 1. 问题从哪来

对应 PDF 第 35–50 页。

上一节留下一个矛盾：模型越大效果越好，但模型越大，每次前向传播的计算也越多。如果我只是回答一个简单问题，真的需要动用全部参数吗？

课件的类比很贴切：一个房间里坐着数学、物理、生物等不同背景的人。你有一个数学问题，需要问遍所有人吗？显然只问数学专家就够了。

MoE（Mixture of Experts，专家混合）就是把这件事做成网络结构：<strong>准备很多个子网络（专家），每个 token 只经过其中少数几个。</strong>

收听音频时要先记这一句：<strong>参数总量可以很大，但每个 token 的计算量由被选中的少数专家决定。</strong>

### 2. 专家、路由器、选择

三个部件，各管一件事：

| 部件 | 作用 | 类比 |
| --- | --- | --- |
| 专家（expert） | 一个独立的小网络，通常是前馈网络 | 某位专家本人 |
| 路由器（router / gate） | 根据当前输入打分，决定派谁上场 | 分诊台 |
| 加权求和 | 把被选中专家的输出按权重合成 | 综合几位专家的意见 |

一个容易误解的地方：这些专家<strong>不是人工指定的学科分工</strong>。它们只是训练出来的数值子网络，没有“数学专家”“语法专家”的标签，最后学成什么分工由训练自己决定。

### 3. MoE 在 Transformer 里的位置

回忆第一讲的结构：每个 Transformer 块里有注意力，也有前馈网络（FFN）。注意力负责位置之间交换信息，FFN 负责逐位置加工特征。

MoE 的常见做法是：<strong>把一部分块里的 FFN 换成一堆 FFN 专家加一个路由器。</strong> 注意力层通常不动。

```text
token 表示 x
  → 注意力（位置之间交换信息）
  → 路由器给每位专家打分
  → 选出 Top-k 位专家
  → 各位专家分别加工 x
  → 按权重相加
  → 进入下一层
```

这带来两个“逐 token 不同”的性质：

- 同一句话里，不同 token 可以去不同专家。
- 同一个 token 在不同层，也可以选不同专家。

所以不能说“这次请求固定用某一个模型”，路由是逐 token、逐层发生的。

### 4. 公式怎么看

```text
路由打分：g(x) = softmax(W x)
选择集合：S(x) = TopK(g(x))
最终输出：y = Σ_{i∈S} wᵢ(x) · Eᵢ(x)
```

逐个读：

- `W x`：用一个矩阵把当前表示变成“每位专家的分数”。
- `softmax`：把分数变成概率，可以理解为“派给每位专家的预算比例”。
- `TopK`：只保留分数最高的 k 位，其余不执行。
- `Eᵢ(x)`：第 i 位专家把同一个 x 加工成新向量。
- `Σ`：把选中专家的输出按权重加起来。

<strong>稠密（dense）与稀疏（sparse）的区别就在 TopK 这一步：</strong>

| 类型 | 计算哪些专家 | 好处 | 代价 |
| --- | --- | --- | --- |
| 稠密 MoE | 全部专家都算，只是权重不同 | 表达平滑 | 计算量随专家数线性增长，意义不大 |
| 稀疏 MoE | 只算 Top-k 个 | 参数可以很多，计算只按 k 计 | 路由、通信、负载均衡都变复杂 |

课件强调：真正有用的是稀疏 MoE。

### 5. 手算一次 Top-2 路由

设路由器给出四个分数，经过 softmax 得到概率：

```text
g(x) = [0.55, 0.25, 0.15, 0.05]
```

Top-2 选中专家 1 和专家 2。这个教学例子采用“选中后重新归一化”的约定：

```text
保留质量 = 0.55 + 0.25 = 0.8
权重 = [0.55/0.8, 0.25/0.8] = [0.6875, 0.3125]
```

设两位专家的输出是二维向量：

```text
E₁(x) = [2, 0]
E₂(x) = [0, 4]
```

逐坐标相加：

```text
第一维：0.6875 × 2 + 0.3125 × 0 = 1.375
第二维：0.6875 × 0 + 0.3125 × 4 = 1.25
y = [1.375, 1.25]
```

这个向量就是该层交给下一步的结果。请注意：<strong>路由概率只负责分配工作量，真正进入下一层的数值来自专家计算。</strong>

现在换成 Top-1 试试。专家 1 仍排第一，独占全部权重，输出就是 `[2, 0]`。同一个 token、同一组分数，k 不同，结果完全不同。这就是 k 是一个需要权衡的超参数的原因。


交互图解「实验：Dense、Top-1 与 Top-2 路由」见[对应章节源文档](../../content/collections/cme295/l2-moe.md)，构建网站后可在该章节操作。


### 6. 总参数与激活参数：为什么数字差那么多

这是看 MoE 模型规格时最容易读错的地方。假设：

- 共享部分（注意力、嵌入、归一化等）共 1B 参数；
- 4 位专家，每位 0.5B；
- 每个 token 只选 2 位。

那么：

```text
总参数 = 1 + 4 × 0.5 = 3B
单 token 激活参数（简化估计）= 1 + 2 × 0.5 = 2B
```

所以一个“3B 参数”的 MoE 模型，前向传播时每个 token 只用到约 2B。这也解释了为什么 MoE 能用相对小的计算量换取较大的容量。

但要注意三点：

- <strong>显存仍要装下总参数</strong>，或者靠分布式放置、卸载来管理。
- <strong>一个 batch 里不同 token 路由不同</strong>，合起来可能用到全部专家。
- <strong>激活参数不等于 FLOPs</strong>，它只是参与计算的参数规模，实际计算还受序列长度、批大小影响。

### 7. 路由塌缩：为什么会出现“富者愈富”

训练初期，某位专家碰巧表现稍好，于是更多 token 被派给它；它得到更多更新，变得更好；于是被派得更多。其他专家几乎没机会学习。

这个现象叫<strong>路由塌缩（routing collapse）</strong>。它的危害是：你以为有 N 位专家，实际有效的可能只有少数几位，模型容量被浪费了。

课件第 45 页用 Switch Transformer 的辅助损失说明缓解办法：

```text
L_aux = α · N · Σᵢ fᵢ · Pᵢ
```

- `fᵢ`：实际被路由到专家 i 的 token 比例（真实分配）。
- `Pᵢ`：路由器给专家 i 的平均概率（模型倾向）。
- `N`：专家总数。
- `α`：辅助损失的权重。

`fᵢ` 与 `Pᵢ` 都是均匀分布时，这个乘积最小；一旦某个专家同时“被偏爱又被实际使用”，乘积变大，损失上升，训练就被推回均衡。

<strong>Top-1 的手算</strong>：N=4，α=0.01。

| 情况 | f | P | L_aux |
| --- | --- | --- | --- |
| 完全均衡 | [0.25, 0.25, 0.25, 0.25] | [0.25, 0.25, 0.25, 0.25] | 0.0100 |
| 偏向一位 | [0.75, 0.25, 0, 0] | [0.7, 0.2, 0.05, 0.05] | 0.0230 |

验算第一种：`0.01 × 4 × (0.25×0.25 × 4) = 0.01 × 4 × 0.25 = 0.01`。偏向一位时损失翻倍以上，说明辅助项确实在惩罚不均衡。

#### 硬选择不可导，路由器怎么学

`TopK` 的“选哪几个”是硬判断，本身不可导。常见做法是：梯度沿路由概率和选中专家的输出回传，而把实际分配比例 `fᵢ` 当作不回传梯度的统计量。不同论文的细节不同，但共同点是<strong>不让梯度穿过那个硬的索引选择</strong>。

### 8. 现在的做法：共享专家与细粒度专家

课件第 49–50 页提到近两年的两个趋势。

<strong>共享专家（shared experts）</strong>：无论路由选谁，某些专家总会被执行。因为总有一些通用计算是每个 token 都需要的，没必要让每位路由专家重复学一遍。

<strong>细粒度专家（fine-grained experts）</strong>：不再用 8 或 16 位大专家，而是用几十到几百位小专家，每次激活其中若干位。专家更专、更细，组合空间更大。课件展示的图表显示，在相近激活参数下，专家数更多的模型效果更好。

<strong>工程代价</strong>：专家越多，跨设备通信、容量上限、token 溢出（某专家满了要丢弃或转发）等问题越突出。所以 k 变小并不必然让端到端延迟线性下降，实际收益要看实现。

课件第 49–50 页列出的具体模型规格是带日期的快照，用来观察量级即可，不要当成长期榜单。

### 9. 理解检查

<details><summary>Top-2 是不是整个模型只有两组参数在算？</summary><p>不是。路由只发生在被改造成 MoE 的那些层；注意力、嵌入、归一化等共享组件照常执行。即使在这些层内，也可能还有共享专家参与。</p></details>
<details><summary>MoE 和多头注意力是不是一回事？</summary><p>不是。多头注意力是同一层里多组投影并行计算注意力；MoE 是在多个 FFN 子网络中挑选少数执行。两者都有“多个分支”，但分工完全不同。</p></details>
<details><summary>为什么说 MoE 省的是计算不是显存？</summary><p>因为总参数仍然需要存放，只是每次前向不必全部参与计算。省计算能提高吞吐，但显存占用和专家间通信并没有自动消失。</p></details>

### 10. 容易记混的地方

- 专家不是人工指定的学科，是训练出来的子网络。
- 路由是逐 token、逐层发生的，不是整次请求选一次。
- 激活参数小于总参数，但显存占用不因此变小。
- 辅助损失是加在主损失上的，不是替换主损失。
- 稀疏意味着每步只算少数专家，不意味着模型整体“简单”。

来源：PDF 第 35–50 页及对应问答。Top-2 数值、辅助损失算例、参数拆分均为教学补充，公式已对照第 45 页核对。


## 位置信息：正弦编码、ALiBi 与 RoPE

### 1. 为什么位置不能省

对应 PDF 第 51–74 页。

先做一个小实验。把两句话交给一个只有注意力的模型：

```text
熊 抱着 孩子
孩子 抱着 熊
```

它看到的是同一批 token，只是顺序不同。如果没有位置信息，注意力只会按“哪些 token 出现”来混合，不会知道谁在前谁在后，于是两句话会得到几乎相同的表示。

这个性质叫<strong>置换等变性（permutation equivariance）</strong>：输入顺序变了，输出只是跟着换个位置，内容关系不变。要区分顺序，就必须显式地把位置信息注入模型。

这就是课件第 52–54 页的出发点。接下来的问题是：位置信息该怎么表示，才能既准确又能推广？

### 2. 方法一：可学习的绝对位置

最直接的做法：给每个位置编号 0、1、2……每个编号配一个可学习的向量，然后加到 token 向量上。

```text
输入 = token 嵌入 + 位置嵌入
xₘ = e(token) + p(m)
```

<strong>好处</strong>：简单，模型自己学该怎样区分位置。

<strong>问题</strong>：位置表是固定长度的。训练时只见过 0 到 511，推理时遇到第 1000 个位置，模型没有任何对应的向量。这叫无法外推（cannot extrapolate）。

课件也提到工程上有办法补救：扩展位置表、插值、继续训练。但这些是补救措施，不是这个方法天然支持任意长度。

### 3. 方法二：正弦编码，用快慢不同的“指针”表示位置

2017 年的原论文提出了一个不需要学习的方案：用固定公式算出每个位置的向量。

先看类比。看一块手表：时针转得慢，分针中等，秒针最快。三根指针各自的读数组合起来，你就能精确知道现在几点。<strong>单个指针有歧义，多个不同频率的指针组合起来才唯一。</strong>

正弦编码就是给位置配一组不同频率的“指针”。

```text
ωᵢ = 10000^(−2i/d)
PE(m, 2i)   = sin(m · ωᵢ)
PE(m, 2i+1) = cos(m · ωᵢ)
```

- `m`：位置编号（第几个 token）。
- `i`：第几组，每组占两个维度。
- `d`：向量总维度。
- `ωᵢ`：这一组的频率。

i 小（靠前）的维度频率高，变化快；i 大（靠后）的维度频率低，变化慢。这正是课件的图：左侧维度随位置剧烈振荡，右侧维度缓慢变化。

#### 手算 d=4 的例子

d=4 时有两组，i=0 和 i=1：

```text
ω₀ = 10000^(−0/4) = 1
ω₁ = 10000^(−2/4) = 10000^(−0.5) = 0.01
```

于是位置 m 的编码是 `[sin(m), cos(m), sin(0.01m), cos(0.01m)]`。

| 位置 m | PE(m) 近似值 |
| --- | --- |
| 0 | [0, 1, 0, 1] |
| 1 | [0.8415, 0.5403, 0.0100, 1.0000] |
| 2 | [0.9093, −0.4161, 0.0200, 0.9998] |

可以看到前两个维度变化很快（0 → 0.84 → 0.91），后两个维度几乎不动（0 → 0.01 → 0.02）。快慢搭配，才能区分“位置 1 和位置 2”又能在长距离上保持平滑。

### 4. 为什么点积能反映相对距离

真正重要的是：两个位置编码的点积，只和它们的距离有关。

先复习一条三角公式：

```text
cos(a − b) = cos a · cos b + sin a · sin b
```

所以对每一组 i：

```text
sin(mωᵢ)sin(nωᵢ) + cos(mωᵢ)cos(nωᵢ) = cos((m − n)ωᵢ)
```

把所有组加起来：

```text
PE(m) · PE(n) = Σᵢ cos((m − n)ωᵢ)
```

右边只出现 `m − n`，也就是距离。这就是课件第 58–65 页想说明的性质。

<strong>自己算一遍位置 0 与位置 1 的点积</strong>（取未舍入的值）：

```text
第一个二维组：0×0.8415 + 1×0.5403 = 0.5403
第二个二维组：0×0.0100 + 1×0.99995 ≈ 0.99995
合计 ≈ 1.5403
```

位置 10 与 11 的点积同样是约 1.5403，因为距离都是 1。这就是“平移不改变点积”的直观含义。

三个必须补充的边界：

- 这个性质说的是<strong>位置编码自身</strong>的点积，不是说完整的注意力分数只由距离决定。token 内容和投影仍会影响。
- 余弦是周期函数，距离越远不一定越不相似，可能出现反弹。
- 公式能给任意新位置算出值，但“能算”不等于“模型能可靠处理任意长度”。

### 5. 把位置放进注意力分数

正弦编码是“加到输入上”，然后随网络往上传。另一种思路是直接改注意力里的匹配分数：

```text
score(m, n) = qₘ · kₙ / √dₖ + b(m, n)
```

课件列了几种加 `b` 的方式：

| 方法 | 怎么加位置 | 特点 |
| --- | --- | --- |
| T5 相对位置偏置 | 按相对距离分桶，每个头学一组偏置 | 距离被离散化，不是每个距离单独学 |
| ALiBi | 给更远的过去位置加线性惩罚 | 不需要位置表，强度按头设定 |
| RoPE | 旋转查询和键 | 位置信息进入匹配本身 |

<strong>ALiBi 的教学写法</strong>：对 n ≤ m，`b(m,n) = −sₕ · (m − n)`。斜率 `sₕ` 每头不同。若 `sₕ=0.5`，当前位置及前三个位置的偏置是 0、−0.5、−1、−1.5。

直觉是：越远越不相关，所以减分越多；但内容本身的分数仍然可以克服这个惩罚，不是硬性屏蔽。

### 6. RoPE：旋转向量

RoPE = Rotary Position Embeddings，出自 RoFormer（2021）。课件在第 68–74 页展开。字幕里的“繩子”是把 rope 当成普通英文词直译了。

#### 先看二维旋转

一个二维向量可以写成“长度 + 角度”：

```text
[x, y] = [r·cosθ, r·sinθ]
```

把它乘上旋转矩阵，角度就增加 φ：

```text
R(φ) = [[cosφ, −sinφ],
        [sinφ,  cosφ]]
```

验证一下：

```text
x' = r cosθ cosφ − r sinθ sinφ = r cos(θ+φ)
y' = r cosθ sinφ + r sinθ cosφ = r sin(θ+φ)
```

这正是三角函数和角公式。<strong>乘旋转矩阵 = 把向量转动 φ 度，长度不变。</strong>

具体例子：`[1, 0]` 旋转 90° 得到 `[0, 1]`，长度仍是 1。课件用度数只是为了好读，实际计算用弧度。

<svg viewBox="0 0 520 220" role="img" aria-label="二维向量旋转：原向量朝右，旋转九十度后朝上" style="width:100%;max-width:520px"><defs><marker id="rope-arrow" markerWidth="8" markerHeight="8" refX="6" refY="3" orient="auto"><path d="M0 0L6 3L0 6Z" fill="#326947"/></marker></defs><g stroke="#a4b6a3"><path d="M80 175H435M110 195V20"/></g><g stroke="#326947" stroke-width="3" marker-end="url(#rope-arrow)"><path d="M110 175H280"/><path d="M110 175V55"/></g><path d="M180 175A70 70 0 0 0 110 105" fill="none" stroke="#b98836" stroke-dasharray="5 3"/><g fill="#24382d" font-size="15"><text x="290" y="180">[1,0]，原方向</text><text x="125" y="55">[0,1]，旋转后</text><text x="170" y="115">90°</text></g></svg>

#### RoPE 的做法

不把位置向量加上去，而是按位置旋转查询（query）和键（key）。位置 m 的查询转 mθ，位置 n 的键转 nθ：

```text
q̃ₘ = R(mθ) qₘ
k̃ₙ = R(nθ) kₙ
```

然后照常做点积：

```text
q̃ₘᵀ k̃ₙ = qₘᵀ R(mθ)ᵀ R(nθ) kₙ
        = qₘᵀ R((n − m)θ) kₙ
```

中间这步用了两个性质：旋转矩阵的转置等于反向旋转，即 `R(φ)ᵀ = R(−φ)`；而 `R(−mθ)R(nθ) = R((n−m)θ)`。

结果里只剩下 `n − m`。<strong>两个绝对角度相消，剩下相对角度</strong>，这正是我们要的。

#### 手算一次

设 θ=30°，m=1，n=3，且 q=k=[1,0]：

```text
q̃ = 旋转 30°  → [cos30°, sin30°] ≈ [0.8660, 0.5]
k̃ = 旋转 90°  → [cos90°, sin90°] = [0, 1]
点积 = 0.8660×0 + 0.5×1 = 0.5
```

而 `cos((3−1)×30°) = cos60° = 0.5`，与点积一致。

再做一次平移检验：把 m、n 同时加 5，变成 6 和 8，距离仍是 2，点积仍是 0.5。这说明位置的作用只取决于相对距离。

同样要说明：这里冻结了 q 和 k 只看位置项。真实模型里，不同位置上的内容向量本身也不同，所以不是说“相隔两格的两个词一定得到同样分数”。

### 7. 高维怎么处理，长距离如何

高维 RoPE 把向量两两分组，`[x₀,x₁]`、`[x₂,x₃]`……每组用不同频率旋转。这样既保留了多尺度信息，又能逐个二维块计算，效率高。

通常只旋转 Q 和 K，V 不参与旋转，因为位置信息只需要影响“匹配”，不需要改变“被取走的内容”。

课件第 74 页讨论长距离下的相对衰减。要点是：<strong>理论上界存在，但不要误读成实际注意力权重随距离单调下降。</strong> 多个频率叠加、内容方向、softmax 竞争都会影响最终权重。

### 8. 为什么今天的模型几乎都用 RoPE

把三种方法放在一起比：

| 方法 | 位置信息加在哪 | 能否外推到更长 | 现状 |
| --- | --- | --- | --- |
| 可学习绝对位置 | 加到输入 | 不能，受表长度限制 | 早期模型 |
| 正弦编码 | 加到输入 | 公式可以算，但模型未必见过 | 原论文，已少用 |
| ALiBi | 加到注意力分数 | 相对距离线性惩罚，较灵活 | 部分模型 |
| RoPE | 旋转 Q 和 K | 相对位置天然内建，可配合插值扩展 | 主流 |

RoPE 胜出的原因可以概括为三点：

1. <strong>相对位置天然出现</strong>，不需要额外设计偏置。
2. <strong>不增加参数</strong>，只是坐标变换。
3. <strong>只作用于注意力</strong>，不影响 FFN 等不关心位置的层，符合直觉。

这三点正是课件在第 66–67 页提出的动机：位置信息应该只影响“谁该关注谁”，不该污染所有层的特征。

### 9. 理解检查

<details><summary>RoPE 是在 token 嵌入上加一个位置向量吗？</summary><p>不是。经典 RoPE 是在注意力内部按位置旋转查询和键，使点积体现相对角度。它和“在入口加位置向量”是两种不同的注入方式。</p></details>
<details><summary>没有可学习位置表，是否意味着能无限扩上下文？</summary><p>不是。公式可以给任意位置算值，但模型是否在该长度上训练过、频率设置是否合适、内存是否够、任务表现是否可靠，都是另外的问题。</p></details>
<details><summary>为什么 RoPE 只旋转 Q 和 K，不旋转 V？</summary><p>位置需要影响的是“两个位置该多关注彼此”，这由 Q 与 K 的匹配决定。V 承载的是被取走的内容，不需要带位置偏移。</p></details>

## 注意力效率：滑动窗口、KV Cache 与 GQA

### 1. 注意力很贵，贵在哪

对应 PDF 第 75–83 页。

先回忆注意力在做什么。每个位置发出一个查询（query，Q），拿它和所有可见位置的键（key，K）做点积，得到匹配程度；再用这些匹配程度作为权重，把对应位置的值（value，V）加权求和。

设序列长度为 n，那么：

```text
每个位置都要和 n 个位置比较 → 共 n × n 个分数
```

n 翻倍，分数变成 4 倍；n 变 10 倍，分数变 100 倍。这就是注意力随序列长度平方增长的来源，也是长上下文昂贵的根本原因。

课件在这一节给出三种不同方向的优化。初学者最容易混淆它们，所以先把三者的分工写清楚：

| 优化 | 改变的是什么 | 省的是 |
| --- | --- | --- |
| 滑动窗口（SWA） | 一个位置<strong>允许看</strong>哪些位置 | 计算量（少算远处连接） |
| KV Cache | 生成时<strong>是否重算</strong>历史键和值 | 重复计算 |
| GQA / MQA | 多个查询头<strong>共享</strong>几组键和值 | 缓存显存与键值投影 |

这三件事可以同时使用，但任何一项都不能推出另外两项。下面逐个展开。

### 2. 滑动窗口：每层只看近邻

SWA = Sliding Window Attention。做法很简单：一个位置只允许看自己左边 w 个位置（w 叫窗口大小）。

以窗口左向 2 为例：

```text
位置：  1 2 3 4 5 6
查询6： × × × ✓ ✓ ✓
查询5： × × ✓ ✓ ✓ ×
```

查询 6 只能看位置 4、5、6，看不到 1、2、3。这样分数从 n×n 降到 n×w，n 增大时线性增长而不是平方增长。

<strong>但信息不会因此断掉。</strong> 关键在多层堆叠：

- 第 1 层：位置 6 读到位置 4。
- 第 2 层：位置 4 的表示里已经含有位置 2 的信息，于是位置 6 间接知道位置 2。
- 第 3 层：再往外扩一圈。

每层向左多看 r 个位置，L 层后理论可达约 L×r + 1 个位置。r=2 时，1、2、3 层分别覆盖 3、5、6 个位置。

这个概念和卷积神经网络里的<strong>感受野（receptive field）</strong>完全同构：单个卷积核只读局部，但堆叠之后能覆盖很大范围。


交互图解「实验：每层只能读自己和左侧 2 个位置」见[对应章节源文档](../../content/collections/cme295/l2-attention-cache.md)，构建网站后可在该章节操作。


课件先讲 Longformer 的稀疏注意力模式，再讲局部与全局层混合的做法，以及 Mistral 的窗口实例。注意一个区别：Longformer 里还有少量<strong>全局 token</strong> 可以看所有人，这不是所有局部注意力模型都有的设计。

<strong>边界</strong>：有信息通路不等于信息被完整保留。窗口会改变模型的计算结构，通常需要相应训练或适配；把一个训练好的全局模型直接截断窗口，不保证效果不变。

### 3. KV Cache：生成时别把前文重算一遍

这是推理优化里最重要、也最常被误解的一步。先用一个具体场景理解它。

假设已有前缀 `A teddy bear`，模型刚预测出 `is`，现在要预测下一个词。回忆自回归生成：每一步都把新 token 接到末尾，再算一遍。

<strong>如果不缓存</strong>：每生成一个 token，都要把整个序列（包括 `A`、`teddy`、`bear`、`is`）重新过一遍所有层。前面那些位置的计算结果和上一次完全一样，却白算了一遍。

<strong>如果缓存</strong>：第一次处理前缀时，把每一层算出的 K 和 V 存下来。之后每生成一个 token，只为这个新位置算新的 Q、K、V，然后：

- 用新 Q 去和“缓存里的历史 K + 新 K”算匹配；
- 用匹配权重去加权“缓存里的历史 V + 新 V”。

这就有两个阶段的名字：

| 阶段 | 做什么 | 特点 |
| --- | --- | --- |
| Prefill（预填充） | 一次性处理整个提示，并写入缓存 | 并行度高，算力密集 |
| Decode（逐 token 解码） | 每步只处理一个新位置 | 串行，访存密集 |

<strong>为什么可以不重算？</strong> 因为因果注意力保证旧位置看不到新位置，权重又是固定的，所以前文那些位置的 K 和 V 不会因为后面加了词而改变。这是 KV Cache 成立的数学前提。

一个常见追问：<strong>Q 要不要缓存？</strong> 不用。Q 是“当前这个位置要问什么”，只在这一步用一次，之后再也用不到。真正反复被读取的是历史 K 和 V。

#### KV Cache 不是“模型记忆”

需要区分清楚：

- KV Cache 是推理过程中的数值中间结果，只在当前对话、当前模型权重下有效；
- 它不是保存聊天摘要，不是知识库检索，也没有改变模型参数；
- 一旦前缀改变或权重更新，旧缓存就失效。

### 4. 多头注意力：为什么会有很多 K 和 V

注意力的“多头（multi-head）”指的是：同一层里并行做多组投影，每组叫一个头，各自关注不同的模式。设查询头数为 h_q。

在标准多头注意力（Multi-Head Attention，MHA）里，每个头都有自己独立的 K 和 V。于是缓存要存的数量正比于头数。

问题来了：<strong>Q 只用一次，K 和 V 却要一直存着。</strong> 头越多，缓存越大。这就是 GQA 的动机。

| 方式 | 键值头数 | 共享关系 | 相对缓存 |
| --- | --- | --- | --- |
| MHA（多头） | 8 | 每个查询头各有独立的 K/V | 100% |
| GQA（分组查询） | 2 | 每 4 个查询头共享一组 K/V | 25% |
| MQA（多查询） | 1 | 8 个查询头共用一组 K/V | 12.5% |

（上表假设 h_q = 8。）

```text
MHA:  Q₁→K₁V₁  Q₂→K₂V₂  Q₃→K₃V₃  … Q₈→K₈V₈
GQA:  Q₁Q₂Q₃Q₄→K₁V₁      Q₅Q₆Q₇Q₈→K₂V₂
MQA:  Q₁…Q₈→K₁V₁
```

GQA 是二者的折中：比 MHA 省缓存，比 MQA 保留更多表达力。MHA 和 MQA 可以看成“共享组数”的两个极端。

<strong>注意</strong>：共享 K/V 不代表所有查询头输出相同。每个 Q 的内容仍不同，只是它们读取同一份键值。

### 5. 亲手算一次缓存占多少

缓存公式（未量化、只算 K 和 V）：

```text
bytes = 2 × B × n × L × h_kv × d_head × bytes_per_value
         ↑K和V ↑batch ↑长度 ↑层数 ↑KV头数 ↑每头维度 ↑每个数值字节
```

逐个理解：

- `2`：K 和 V 各一份。
- `B`：同时处理的请求数（batch size）。
- `n`：序列长度。
- `L`：层数，每层都要单独存。
- `h_kv`：键值头数，GQA 的关键变量。
- `d_head`：每个头的维度。
- `bytes_per_value`：每个数值占几个字节，FP16 是 2。

#### 从小单位开始算

先算“一层、一个位置、一个头”的键值对：

```text
2（K和V）× 128（维度）× 2（字节）= 512 字节
```

再放大到 8 个 KV 头：

```text
512 × 8 = 4096 字节/位置/层
```

再放大到 4096 个位置：

```text
4096 × 4096 = 16,777,216 字节 = 16 MiB（每层）
```

再放大到 32 层：

```text
16 MiB × 32 = 512 MiB
```

这就是完整 MHA 在 B=1、n=4096、L=32、d_head=128、FP16 下的缓存量。

换成 GQA（h_kv=2），每一步都除以 4：

| 模式 | h_kv | 字节 | 换算 |
| --- | --- | --- | --- |
| MHA | 8 | 536,870,912 | 512 MiB |
| GQA | 2 | 134,217,728 | 128 MiB |
| MQA | 1 | 67,108,864 | 64 MiB |

注意 1 MiB = 1,048,576 字节，不是 1,000,000。

<strong>这个数字只包含 K/V。</strong> 模型权重、激活值、临时工作区、显存碎片、多个并发请求都还没算。所以真实显存占用会比这个大不少。

<strong>再试一个</strong>：如果 batch 从 1 变成 4，其他不变，缓存变成多少？答案是 4 倍，因为每个请求都要独立存一份。

### 6. 三种优化怎么配合

它们解决的是不同层次的问题，可以叠加：

```text
滑动窗口 → 减少每次要比较的 K/V 数量（n 从全长变成 w）
KV Cache → 避免重复计算历史 K/V
GQA      → 减少每个位置需要存储的 K/V 份数
```

举个组合场景：一个使用 GQA、窗口 4096 的模型，在长文本上既要算得快（窗口限制），又不能每步重算（缓存），显存还要可控（共享 KV 头）。三者缺一不可。

### 7. 理解检查

<details><summary>用了 KV Cache，每步还需要读历史吗？</summary><p>需要。新 Q 仍要和可见的历史 K 算匹配，再汇总历史 V。缓存省掉的是“重新生成历史 K/V”的计算，不是所有历史读取。</p></details>
<details><summary>GQA 能把端到端速度提高 4 倍吗？</summary><p>不能这样保证。缓存容量按公式确实缩小 4 倍，但实际速度还受带宽、其他算子、批大小和内核实现影响。缓存变小主要改善的是“能放多长”和“能并发多少”。</p></details>
<details><summary>滑动窗口会不会丢掉远处信息？</summary><p>单层会，但多层堆叠后信息可以间接传播，就像卷积的感受野。代价是精确的远处细节可能被压缩或丢失，不是无损保留。</p></details>

### 8. 容易记混的地方

- KV Cache 缓存的是 K 和 V，不是 Q，也不是“整段对话的语义”。
- Prefill 是并行处理提示，Decode 是逐 token 生成，两者耗时特征不同。
- GQA 减的是 KV 头数，不是查询头数。
- 滑动窗口和 GQA 都可以减少成本，但一个减位置、一个减份数，不能互相替代。
- MiB 与 MB 差约 4.8%，大数上不能混用。

## 归一化：Pre-Norm 与 RMSNorm

### 1. 这一节其实有两个独立问题

对应 PDF 第 84–88 页。初学者读到“Pre-Norm”“RMSNorm”会以为它们是同一件事的两种叫法，其实它们回答的是完全不同的问题：

| 问题 | 答案选项 | 关心什么 |
| --- | --- | --- |
| 归一化放在子层的哪一侧？ | Post-Norm / Pre-Norm | 梯度能不能顺畅流回去 |
| 用哪个公式做归一化？ | LayerNorm / RMSNorm | 要不要减均值、要不要学两组参数 |

这两件事可以自由组合。今天的模型常见的是 Pre-Norm 加 RMSNorm，但这不是唯一搭配，也不是说“Pre-Norm 就是 RMSNorm”。

### 2. 先理解残差连接

要理解“放在哪一侧”，先要知道子层长什么样。

一个 Transformer 块里的子层（注意力或 FFN）接收输入 x，加工成 f(x)。残差连接（residual connection）的做法是：

```text
输出 = x + f(x)
```

为什么可以简单相加？因为 x 是一条直通路径：梯度可以沿这条路直接回传，不必穿过 f 的所有运算。这对几十层、上百层的网络能否训练起来至关重要。

归一化的位置问题，就是问：这个 Norm 放在 `x + f(x)` 的外面，还是里面？

### 3. Post-Norm 与 Pre-Norm

```text
Post-Norm: y = Norm(x + f(x))      ← 先相加，再归一化
Pre-Norm:  y = x + f(Norm(x))      ← 先归一化，再进子层
```

（省略了 dropout，不影响这里的讨论。）

<div class="flow"><span class="chip">Post：x → f → 与 x 相加 → Norm</span><span class="chip">Pre：x → Norm → f → 与 x 相加</span></div>

用一句话说清区别：

- <strong>Post-Norm</strong>：残差主通路上的数值每经过一个子层就被 Norm 改写一次。
- <strong>Pre-Norm</strong>：残差主通路始终保持 `x` 的原样，Norm 只作用在子层支路里。

原论文用的是 Post-Norm。后来的模型逐渐改成 Pre-Norm，原因是深层网络里 Post-Norm 容易训练不稳：主通路上的数值反复被归一化，梯度回传时受到限制，常常需要精心调学习率预热（warmup）才能训起来。

Pre-Norm 让主通路“干净”，梯度更容易从深层传回浅层，训练更稳。

<strong>但别过度承诺</strong>：Pre-Norm 不保证“任何深度都必然能训”，它只是改善了条件。初始化、优化器、数值精度、层数仍然都影响训练。另外，Pre-Norm 的输出没有被归一化，越深数值可能越大，有些实现会在最后一层后补一个 Norm，就是为了这个原因。

### 4. LayerNorm：减均值，再按标准差缩放

现在看公式本身。对一个 token 的 d 维表示 x：

```text
μ = mean(x)
σ² = mean((x − μ)²)
LN(x) = γ ⊙ (x − μ) / √(σ² + ε) + β
```

逐个拆解：

- `μ`：这一串数的平均值。
- `x − μ`：减去均值，叫<strong>中心化（centering）</strong>，让结果均值为 0。
- `σ²`：方差，衡量这串数有多分散。
- `(x − μ)/√(σ² + ε)`：再除以标准差，让结果方差接近 1，叫<strong>缩放（scaling）</strong>。
- `ε`：很小的常数，防止除以 0。
- `γ`、`β`：可学习的缩放和偏移，让模型自己决定要不要恢复一些幅度和位置。
- `⊙`：逐项相乘。

注意计算方向：是<strong>沿着特征维度</strong>算的，也就是对“这个 token 自己的那一串数”统计，而不是把不同 token 混在一起。

#### 用 [1, 3] 算一遍

为了好算，先取 γ=[1,1]、β=[0,0]，并忽略 ε：

```text
μ = (1 + 3) / 2 = 2
x − μ = [1−2, 3−2] = [−1, 1]
σ² = ((−1)² + 1²) / 2 = 1
σ = 1
LN([1,3]) = [−1, 1]
```

结果均值是 0（(−1+1)/2 = 0），方差是 1。这就是 LayerNorm 想做成的样子。

### 5. RMSNorm：不减均值，只按均方根缩放

RMSNorm 的公式：

```text
RMS(x) = √(mean(x²))
RMSNorm(x) = γ ⊙ x / √(mean(x²) + ε)
```

和 LayerNorm 比，它少了两件事：不减均值，通常也没有偏移项 β。只做缩放。

同样用 [1,3]，γ=[1,1]，忽略 ε：

```text
mean(x²) = (1² + 3²) / 2 = (1+9)/2 = 5
RMS = √5 ≈ 2.236
RMSNorm([1,3]) = [1/2.236, 3/2.236] ≈ [0.4472, 1.3416]
```

对比一下：

| 对比项 | LayerNorm | RMSNorm |
| --- | --- | --- |
| 减均值？ | 是 | 否 |
| 缩放依据 | 标准差 | 均方根 |
| 输出均值一定为 0？ | 减均值后是，加 β 后不一定 | 本来就不要求 |
| 可学习参数 | γ 和 β | 通常只有 γ |
| [1,3] 的结果 | [−1, 1] | [0.4472, 1.3416] |

<strong>RMSNorm 的输出为什么不是 0 均值？</strong> 因为它保留了整体偏移，只统一调整尺度。它关心的不是“让数据对称”，而是“让数据的幅度可控”。

<strong>为什么能省？</strong> 少算一次均值、少一组参数、少一次减法，在大模型里累积起来是可观的。经验上效果与 LayerNorm 相当，所以现在很多模型用它。

### 6. 动手验证“减均值”到底去掉了什么

把输入整体加 2，从 [1,3] 变成 [3,5]。猜猜哪个算子的输出会变？

<strong>LayerNorm</strong>：

```text
μ = (3+5)/2 = 4
x − μ = [−1, 1]
σ² = 1
LN([3,5]) = [−1, 1]
```

和 [1,3] 的结果完全一样。因为“整体平移”这个信息被减均值抹掉了。

<strong>RMSNorm</strong>：

```text
mean(x²) = (9+25)/2 = 17
RMS = √17 ≈ 4.123
RMSNorm([3,5]) = [3/4.123, 5/4.123] ≈ [0.7276, 1.2127]
```

结果变了。RMSNorm 保留了“整体偏移”的信息，只压缩幅度。

这就是两者最本质的差别：<strong>LayerNorm 对整体平移不敏感，RMSNorm 对整体平移敏感。</strong> 至于哪个更好，取决于任务和训练动态，没有普适答案。

### 7. 位置与公式不要混为一谈

用同一个教学子层 `f(u) = 2u`，输入 x=[1,3]，γ、β 照旧：

```text
Post-LN: LN(x + f(x)) = LN([1,3] + [2,6]) = LN([3,9])
       = [−1, 1]

Pre-LN:  x + f(LN(x)) = [1,3] + 2×[−1,1]
       = [1,3] + [−2,2]
       = [−1, 5]
```

两个结果不同。这不是算术巧合，而是说：<strong>归一化的位置和归一化的公式都会改变数值，两者不能互相替代。</strong>

真实子层不是这么简单的线性函数，所以把一层搬来搬去不会“保持原模型不变”。

### 8. 现代模型的常见组合

| 时期 | 常见组合 | 原因 |
| --- | --- | --- |
| 原论文 | Post-Norm + LayerNorm | 当时的标准做法 |
| 后来的深层模型 | Pre-Norm + LayerNorm | 深层更容易训练 |
| 现在的主流 | Pre-Norm + RMSNorm | 训练稳定且更省计算 |

课件字幕里“术前／术后正常化”“色情内容”都是 Pre/Post-Norm 的误译，读的时候按英文原词理解。

### 9. 理解检查

<details><summary>RMSNorm 会不会把每个数都变成 1？</summary><p>不会。它是统一除以一个尺度，保留分量之间的比例。例子中 [1,3] 变成约 [0.4472, 1.3416]，比例仍是 1:3。</p></details>
<details><summary>Pre-Norm 和残差是不是重复的功能？</summary><p>不是。残差提供 x 的直通路径；Pre-Norm 决定归一化在支路中的位置。两者协同影响优化，但职责不同。</p></details>
<details><summary>为什么深层模型偏爱 Pre-Norm？</summary><p>它让残差主通路不被反复归一化，梯度更容易回传，训练更稳。但这不等于 Post-Norm 无法训练，只是通常需要更仔细的超参数设置。</p></details>

### 10. 容易记混的地方

- Pre/Post 说的是<strong>位置</strong>，Layer/RMS 说的是<strong>公式</strong>。
- RMSNorm 不减均值，不是“更简化版的减均值”。
- 归一化在特征维度上做，不跨越 token。
- ε 只是防除零，不影响概念。
- γ、β 是可学习的，所以“LayerNorm 输出均值必为 0”在完整公式下不成立。

来源：PDF 第 84–88 页及字幕，第 85–87 页已视觉核对。数值例子省略 ε 并固定 γ、β，为教学补充。


## 解码策略：贪心、Beam、温度与约束生成

### 1. 模型只给概率，文字是选出来的

对应 PDF 第 89–123 页。

先接住上一节的结论：模型最后输出的是词表上每个候选的分数（logit），经 softmax 变成概率。比如只有两个候选时：

```text
reading  : 0.6
sleeping : 0.4
```

这一节的全部内容，就是回答一个问题：<strong>拿到这份概率之后，怎么变成一个 token？</strong>

```text
上下文 → 网络 → logits → 概率 → 【选择策略】→ token → 追加 → 重复
```

把方框里的东西换掉，模型其实一点没变。这是理解这一节最重要的一句话，也是很多初学者困惑的来源：同一个问题两次答案不同，往往不是模型变了，而是选择策略带了随机性。

### 2. 贪心：每一步都挑当前最高分

<strong>Greedy decoding</strong> 规则极简：`argmax`，取概率最大的那个。

对上面的分布，永远选 `reading`。

<strong>好处</strong>：简单、确定、快。

<strong>坏处</strong>：每一步局部最优，不等于整条序列最优。举个完整的两步反例，第一步 A 概率 0.6、B 概率 0.4，第二步的条件分布是：

| 已选前缀 | 下个选 X | 下个选 Y | 两步联合概率 |
| --- | --- | --- | --- |
| A | 0.51 | 0.49 | P(AX)=0.6×0.51=0.306 |
| B | 0.99 | 0.01 | P(BX)=0.4×0.99=0.396 |

贪心第一步选 A，第二步在 A 后面选 X，得到 AX，概率 0.306。但 BX 的概率是 0.396，更高。

原因很清楚：贪心在第一步把 B 整条路径丢掉了，而 B 后面接 X 几乎是必然。<strong>要避免这个损失，就得保留多个前缀</strong>，这正是 beam search 的思路。

### 3. Beam search：同时保留 k 条路

<strong>Beam search</strong> 不贪心地丢掉次优项，而是每一步都保留 k 条最优前缀（k 叫 beam width）。

k=2 时，沿用上面的概率：

```text
第一步保留：A(0.6)、B(0.4)
第二步扩展：
  AX = 0.6 × 0.51 = 0.306
  AY = 0.6 × 0.49 = 0.294
  BX = 0.4 × 0.99 = 0.396
  BY = 0.4 × 0.01 = 0.004
保留前两名：BX(0.396)、AX(0.306)
```

于是它找到了贪心错过的 BX。

实现上通常用对数概率相加，而不是直接乘，因为长序列连乘会下溢到 0：

```text
log P = Σ log pᵢ
```

<strong>边界</strong>：beam search 是受限搜索，不是全局最优；不同长度的序列概率不能直接比较（需要长度归一化）；beam 越大越慢；而且“概率最高”不等于“最有用、最真实、最有创意”。

### 4. 采样：按概率抽，而不是总取第一

回到 `[0.6, 0.4]`。<strong>采样（sampling）</strong>的做法是：按概率抽一次。

在纸上模拟：画一条单位长的线段，`reading` 占左段 0.6，`sleeping` 占右段 0.4。均匀随机取一个数：

- 取到 0.3 → 落在左段 → 选 `reading`
- 取到 0.7 → 落在右段 → 选 `sleeping`

长期平均下，`reading` 被选中的比例约为 60%，但单次可能选到任何一个非零候选。

<strong>为什么这很重要？</strong> 因为贪心是确定性的：同一提示永远同一答案。课件举的例子是，如果你和你的朋友问同一句“你好”，得到一模一样的回复，会显得机械。人类对相似问题也会给出不同措辞。

<strong>随机性不总是好事。</strong> 课件也说明了什么时候需要确定性：

- 需要可复现的实验和评测；
- 文本摘要这类希望稳定输出的任务；
- 作为评审（LLM-as-a-judge）时，希望打分一致。

所以这不是二选一，而是可调的参数。

### 5. Top-k 与 Top-p：先剪枝，再采样

直接从整个词表采样有风险：词表几万到几十万，长尾里的荒谬词也可能被抽中。两种常见剪枝方法：

#### Top-k：固定保留前 k 个

k=2，保留前两名，总概率 0.65，重新归一化：

```text
[0.40, 0.25] / 0.65 ≈ [0.6154, 0.3846]
```

然后从这两个里抽。

注意：Top-k 不是“强制每 k 步换一个词”，也不是“取前 k 个词拼成句子”，它只是限制候选集合。

#### Top-p（nucleus sampling）：固定保留多少概率质量

按概率从大到小累加，取<strong>第一次达到或超过 p</strong> 的最小前缀。

用分布 `[0.40, 0.25, 0.20, 0.10, 0.05]`：

| p 阈值 | 保留 | 原质量 | 归一化后 |
| --- | --- | --- | --- |
| 0.60 | [0.40, 0.25] | 0.65 | [0.6154, 0.3846] |
| 0.80 | [0.40, 0.25, 0.20] | 0.85 | [0.4706, 0.2941, 0.2353] |
| 0.90 | [0.40, 0.25, 0.20, 0.10] | 0.95 | [0.4211, 0.2632, 0.2105, 0.1053] |

关键点：<strong>p=0.8 不代表保留“概率小于 0.8 的词”</strong>，也不是固定保留几个词。加入第三项后累计从 0.65 跳到 0.85，已经超过 0.8，就停在这里。

Top-k 与 Top-p 同时用时，先后顺序和具体约定要看服务实现。

### 6. 温度：调分布的“陡峭程度”

温度 T 直接在 softmax 里起作用：

```text
pᵢ(T) = exp(zᵢ / T) / Σⱼ exp(zⱼ / T)
```

- T < 1：分布更<strong>尖</strong>，高分候选更占优势。
- T = 1：原样。
- T > 1：分布更<strong>平</strong>，低分候选机会更大。

#### 用单位线段再模拟一次

原始分布 `[0.6, 0.4]`，现在把 T 从 1 调到 0.5。分数除以 0.5 等于乘 2，指数运算后相当于把原概率各自平方再归一化：

```text
0.6² = 0.36，0.4² = 0.16
归一化：0.36/(0.36+0.16) = 0.36/0.52 ≈ 0.6923
新分布 ≈ [0.6923, 0.3077]
```

线段左段从 0.6 拉长到 0.6923。如果这次抽到 0.7，<strong>调整前后都落在右段</strong>，选的还是 `sleeping`。但如果抽到 0.65：

- 原分布：0.65 > 0.6 → 选 `sleeping`
- 新分布：0.65 < 0.6923 → 选 `reading`

同一个随机数，温度不同，结果不同。

<strong>注意两个容易误解的点：</strong>

1. 温度不改变候选的排序。除以正数不改变大小关系，它改变的是概率差距。
2. 温度不是“开关”，是连续可调的旋钮。


交互图解「实验：同样的 logits [2,1,0,−1]，只改变温度」见[对应章节源文档](../../content/collections/cme295/l2-decoding.md)，构建网站后可在该章节操作。


#### T=0 是怎么回事

数学上 T=0 会让公式除零，没有定义。API 里的 `temperature=0` 通常是约定：进入贪心或近似确定性模式。

而“T→0⁺ 时集中到最大项”也有前提：最大项必须唯一。如果有并列最大值，还要看 tie-break 规则。

### 7. 为什么 T=0 也不能保证完全复现

课件第 115–116 页讨论了这一点。直觉上，权重固定、输入固定、运算固定，结果应该固定。但实际服务中有个因素被忽略了：<strong>批处理</strong>。

推理引擎会把你的请求和其他请求打包成一个 batch 一起算。而浮点加法不满足结合律：

```text
(10¹⁶ + (−10¹⁶)) + 1 = 1
10¹⁶ + ((−10¹⁶) + 1) = 0
```

（IEEE 754 双精度下）

加法顺序变了，结果就可能差一点点。当两个候选分数极其接近时，这一点差别就能翻转 argmax 的结果。

这个现象叫“批处理不变性（batch invariance）不存在”。课件推荐了 Horace He 关于这一点的博客文章。

<strong>要真正复现，需要固定的不止温度</strong>：模型版本、提示模板、工具返回结果、随机种子、运行环境与批处理配置都需要控制。

### 8. 约束解码：只允许合法的下一步

工业场景常需要结构化输出，比如 JSON。如果格式错了，下游解析就会失败。

<strong>第一种做法</strong>：直接要求。“请用 JSON 输出。” 今天大多数模型能做到，但不是 100%。

<strong>第二种做法</strong>：<strong>受约束解码（guided / constrained decoding）</strong>。它根据目标语法限制下一步可选的 token：

```text
模型 logits → 语法状态检查 → 把不合法候选的分数设为 −∞
→ 在合法集合内归一化 → 选择
```

例如目标 `{"age": 33}`，当已经生成到 `{"age":` 时，语法状态知道下一个必须是一个整数的开头，于是所有不可能是数字起点的 token 都被屏蔽。

<div class="flow"><span class="chip">模型 logits</span><span class="arrow">＋ 语法状态 →</span><span class="chip">屏蔽不合法候选</span><span class="arrow">→ 选择 →</span><span class="chip">更新语法状态</span></div>

<strong>一个必须说清的边界</strong>：字符级和 token 级不是一一对应的。一个 token 可能包含多个字符，所以实现需要做 token 到语法状态的转换，不能简单把每个 token 当一个字符处理。

<strong>更重要的边界</strong>：<strong>格式合法不等于事实正确。</strong> 符合 Schema 的 `age: 33` 完全可能是编造的。要保证正确，还需要字段校验、来源核对和业务验证。

### 9. 一张表记住各策略

| 策略 | 是否随机 | 主要优点 | 主要风险 |
| --- | --- | --- | --- |
| Greedy | 否 | 简单、可复现 | 局部最优陷阱 |
| Beam search | 否 | 兼顾多个前缀 | 慢；最高概率≠最有价值 |
| 纯采样 | 是 | 多样、自然 | 可能抽到荒谬词 |
| Top-k | 是 | 剪掉长尾 | k 固定，不适应分布形状 |
| Top-p | 是 | 随分布自适应 | 阈值需要调 |
| 温度 | 是（配合采样） | 连续调控多样性 | 高温更易跑题 |
| 约束解码 | 视情况 | 保证格式 | 不保证内容正确 |

### 10. 理解检查

<details><summary>Top-p=0.8 时，累计质量为什么可能是 0.85？</summary><p>因为候选不能拆成半个。加入第三项后从 0.65 跳到 0.85，首次达到阈值就停止，再把保留集合归一化。</p></details>
<details><summary>温度调低会不会改变最可能 token 的排序？</summary><p>不会。除以正温度不改变 logit 的大小顺序，只改变概率差距。但实际输出仍可能因采样、舍入和并列规则而不同。</p></details>
<details><summary>约束解码能保证输出正确吗？</summary><p>不能。它只保证语法或结构合法，内容的真假仍要靠数据校验和事实核对。</p></details>

## 上下文、提示与推理：给什么、怎么给？

### 1. 上下文到底是什么

对应 PDF 第 124–137 页。

上一节讲到：每选出一个 token，就把它接回输入，再预测下一个。这意味着<strong>模型看到的输入一直在变长</strong>。

把它写成一段纸面过程，会非常直观。先写：

```text
A cute teddy bear is
```

模型选出 `reading`，你把它写到同一行末尾：

```text
A cute teddy bear is reading
```

现在拿手盖住 `reading`，你会发现下一轮少了一条重要线索。因为你盖住的正是下一轮必须看到的内容：<strong>刚生成的 token 既是这一轮的输出，也是下一轮的输入。</strong>

这就是<strong>上下文窗口（context window）</strong>的含义：模型一次能处理的最大长度，包含系统说明、历史消息、用户问题、工具返回结果，以及已经生成的 token。

初学者常误以为“上下文窗口 = 我在输入框里写的内容”。不是。它是“输入 + 已输出”的总体积。

| 概念 | 含义 | 容易误解的点 |
| --- | --- | --- |
| 上下文窗口 | 模型一次能处理的总长度 | 以为只算用户输入 |
| 最大输出 | 本次允许生成的上限 | 以为等于窗口大小 |
| 输入 token | 提示部分 | 包含系统提示、示例、历史 |
| 输出 token | 生成部分 | 生成后也占用窗口 |

具体 API 对输入、输出、缓存和推理 token 的计数方式不同，必须查当前版本文档。

### 2. 算一次预算

教学假设：总窗口 8192 token，所有输出都计入总预算，独立输出上限 2048：

```text
系统与模板   500
历史与资料  3500
用户问题    1000
输入合计    5000

总窗口剩余 = 8192 − 5000 = 3192
实际允许输出 = min(3192, 2048) = 2048
```

注意不是“用户文字没到 8192，就还能输出 8192”。如果你的历史很长，输入已经吃掉大部分预算，输出空间会被压缩到很小，甚至无法完成回答。

<strong>工具描述、系统提示、模板里的固定文字都会占位。</strong> 这些是初学者最容易漏算的部分。

### 3. token 和页数，只能粗估

课件第 129–130 页用的英文经验值是：

- 1 token ≈ 0.75 个英文单词
- 一页约 400 词 ≈ 533 token，课堂取整为 500

这个估计依赖字体、排版、语言和分词器。中文、代码、表格都没有“一个字一个 token”的固定换算。要估算成本和长度，应该用目标模型的分词器实际统计。

课件第 126–128 页给出的产品规格是材料日期的快照，不代表所有模型现在的限制。

### 4. 上下文更长，为什么有时反而更差

直觉上，信息越多越好。实际有一个现象叫<strong>上下文腐化（context rot）</strong>：输入变长后，关键信息被大量无关内容稀释，模型反而更难用上它。

评测方法叫 <strong>Needle in a Haystack（大海捞针）</strong>：把一条关键事实藏在长上下文的不同位置，看模型能否找回来。

```text
任务：熊 A 今年几岁？
关键事实：熊 A 今年 4 岁。
噪声：几百页其他玩具的无关记录
```

结论是：<strong>“能接收这么多 token”是容量能力，不等于“能可靠利用每一段信息”。</strong>

但也不要把任何长输入都断言成“必然更差”。不同任务、不同模型、不同位置差异很大。可行做法是：

1. 明确任务需要哪些信息；
2. 检索并只放入相关资料；
3. 删掉重复和无关内容；
4. 必要时先摘要；
5. 完成后核对是否还能回答任务。

压缩也会丢信息，所以压缩后要验证。

### 5. ICL：不改变权重，靠上下文学习

<strong>上下文学习（In-Context Learning，ICL）</strong>指：模型根据当前输入里的说明或示例调整回答，<strong>不更新任何参数</strong>。

这是它和微调最本质的区别：

| 方式 | 改参数吗 | 数据要求 | 生效范围 |
| --- | --- | --- | --- |
| 提示（zero-shot） | 否 | 只需说明 | 当前请求 |
| 少样本（few-shot） | 否 | 几个示例 | 当前请求 |
| 微调（fine-tuning） | 是 | 成百上千带标签样本 | 之后所有请求 |

#### zero-shot：只给任务和事实

```text
已知：熊 A 在 2024 年是 4 岁。
问题：2025 年熊 A 是几岁？
要求：只输出年龄数字。
```

期望输出 5。注意 zero-shot 指的是<strong>没有任务示范</strong>，不是“不许给任何背景信息”。事实仍然要给。

#### few-shot：给几个输入输出示例

```text
例子：熊 B 在 2024 年是 3 岁 → 2025 年是 4 岁。
例子：熊 C 在 2024 年是 6 岁 → 2025 年是 7 岁。
已知：熊 A 在 2024 年是 4 岁 → 2025 年是？
```

示例同时传达两件事：任务规则（加一年）和输出格式（只要数字）。

一个需要警惕的地方：<strong>如果示例和查询过于相似，就变成了泄漏答案</strong>，那不是有效的评测或演示。

### 6. 示例该怎么调

假设模型输出了“熊 A 是 5 岁”，而你的程序要读一个整数。可以这样一步步诊断：

1. <strong>先加格式要求</strong>：在提示末尾写“只输出整数”，同一题重试。
2. <strong>再换测试题</strong>：把年份和年龄都换掉，看格式要求是否迁移到新输入。
3. <strong>需要 JSON 时</strong>：用约束解码限制格式，再由程序校验字段值。

如果输出确实只有一个整数，但值错了，比如抄了示例里熊 B 的年龄，那该查哪里？

试着<strong>删掉熊 B 的示例</strong>，只保留熊 A 的事实，再问一次；然后把示例加回来，其余不变。对比两次输出，就能判断示例是否干扰了任务。

要判断某种提示整体更可靠，还需要在一组留出的题目上分别统计：

- 格式合格率（能不能被解析）；
- 答案正确率（数值是否对）。

<strong>这两个指标必须分开看</strong>，因为它们衡量的是不同的东西。

### 7. CoT：把中间步骤写出来

<strong>思维链（Chain-of-Thought，CoT）</strong>的核心思路是：与其让模型直接给答案，不如先展示推理步骤。

课件介绍的历史做法是用几个“问题 + 分步解答”的示例，引导模型也写出步骤。作者发现模型会学到这种推理路径，多步任务的表现随之提高。

用一个<strong>可验证的简短算式</strong>展示：

```text
题目：2024 年 4 岁，2025 年几岁？
步骤：2025 − 2024 = 1
答案：4 + 1 = 5 岁
```

固定用 2024→2025，避免把随日期变化的事实混进计算（字幕里出现了“现在”“明年”等不同说法，容易产生歧义）。

<strong>三个必须说清的边界：</strong>

1. 写出的步骤不一定忠实反映模型的内部计算过程。它可能是事后的合理化解释。
2. 步骤看起来合理，不保证答案正确。
3. CoT 不是唯一手段。现在有专门用推理 token 训练的推理模型，机制与此不同，后面讲座会讨论。

实用建议：要求简短理由、引用来源和结果验证，比强求完整“内心独白”更可靠。

### 8. 自洽性：多采样几次再投票

<strong>自洽性（self-consistency）</strong>的做法是：同一道题生成多个答案，再按最终答案聚合。

```text
采样结果：[5, 5, 4, 5, 4]
答案 5 得 3 票 → 选 5
```

<div class="flow"><span class="chip">同一问题</span><span class="arrow">→ 多次采样 →</span><span class="chip">5 / 5 / 4 / 5 / 4</span><span class="arrow">→ 聚合 →</span><span class="chip">多数答案：5</span></div>

它本质上是<strong>用更多推理计算换准确率</strong>，不是训练新模型。

<strong>关键警告：票数比例不是正确概率。</strong> 如果 5 个样本高度相关（比如同一种误解），多数票也会错。要让它有效，需要：

- 采样有真正的多样性（温度不能太低）；
- 统一答案格式，否则无法聚合；
- 处理并列情况；
- 结合独立计算或事实核对。

### 9. 把四个层次分开

初学者常把下面四件事混为一谈，其实它们改的是完全不同的东西：

| 层次 | 改变什么 | 例子 |
| --- | --- | --- |
| 提示 | 模型看到的上下文 | 加两个示例 |
| 解码 | 从分布里怎么选 | 降低温度 |
| 参数 | 模型本身 | 微调 |
| 推理时计算 | 采样几次、怎么聚合 | 自洽性投票 |

“给年龄题加两个例子”不是微调；“要求 JSON”也不是严格语法约束本身。它们可以组合使用，但要分别验证效果和成本。

### 10. 理解检查

<details><summary>few-shot 为什么会增加延迟和费用？</summary><p>示例增加输入 token，预填充计算和缓存可能增加。缓存命中、服务计费和生成长度也影响实际成本，不能简单按示例个数推断倍数。</p></details>
<details><summary>自洽性得到 5 的票数是 60%，能说答案有 60% 概率正确吗？</summary><p>不能。这只是该采样集合中的频率，样本独立性和模型偏差都会影响它，需要另外校准或验证。</p></details>
<details><summary>上下文更长一定更好吗？</summary><p>不一定。容量支持更长不等于能可靠利用。关键词被稀释时可能出现上下文腐化，所以检索、精简和核对都很重要。</p></details>

来源：PDF 第 124–137 页及字幕，第 125、137 页已视觉核对。窗口预算、固定年份例子与诊断流程为教学补充。


## 第二讲复习：一张对照表串起 LLM

### 1. 一次请求走完全部组件

复习最好的方式，是把整讲的零件串成一条时间线。假设提示是：

```text
熊 A 在 2024 年 4 岁，请输出 2025 年年龄的 JSON。
```

1. <strong>分词与预算检查</strong>：提示被切成 token，同时检查输入和输出预算够不够（对应[上下文](../../content/collections/cme295/l2-context-reasoning.md)）。
2. <strong>进入网络</strong>：token 变成嵌入向量，位置机制（例如 RoPE）把顺序信息带进来（对应[位置](../../content/collections/cme295/l2-position.md)）。
3. <strong>逐层处理</strong>：注意力按可见范围读取上下文；FFN 或 MoE 处理每个位置；Pre-Norm、RMSNorm 控制数值（对应[模型家族](../../content/collections/cme295/l2-model-families.md)、[MoE](../../content/collections/cme295/l2-moe.md)、[归一化](../../content/collections/cme295/l2-normalization.md)）。
4. <strong>缓存复用</strong>：前文的键和值已经存在 KV Cache 里，新 token 只算自己的部分（对应[注意力与缓存](../../content/collections/cme295/l2-attention-cache.md)）。
5. <strong>输出分布</strong>：隐藏表示投影成 logits，温度调整形状，Top-k/Top-p 剪枝（对应[解码](../../content/collections/cme295/l2-decoding.md)）。
6. <strong>约束与选择</strong>：若启用约束解码，屏蔽不符合 JSON 语法的续写，再选出 token。
7. <strong>回填</strong>：选出的 token 追加到上下文，回到第 1 步，直到结束。
8. <strong>校验</strong>：检查 JSON 能解析，再检查 age 是否真的等于 5。

最后一步是很多人忽略的：<strong>格式合法、计算正确、事实准确，是三件不同的事。</strong>

这是教学组合例子，不表示所有模型都同时使用 MoE、GQA 和同一套归一化。

### 2. 六条主线对照表

| 课件章节 | 记住这一句 | 典型误解 |
| --- | --- | --- |
| 模型家族 | 区别在于一个位置能看见谁 | “decoder-only 理解不了输入” |
| 缩放法则 | 参数、数据、训练与推理预算共同决定方案 | “模型更大一定更省钱” |
| 专家路由 | 每个 token 只执行少数专家 | “总参数等于每次激活参数” |
| 架构优化 | 位置、可见范围、缓存、共享头、归一化各有分工 | “GQA 就是缩短窗口” |
| 解码 | 模型给概率，策略做选择 | “Top-p=0.8 就是保留 80% 的词” |
| 提示与推理 | 不改参数地组织上下文、示例和采样 | “解释流畅就代表推理真实且正确” |

### 3. 热身题

对前缀 `A cute teddy bear is`，模型给 `reading` 最高分，采样却选中了 `sleeping`。下一步该把哪个 token 送回模型？前面哪些计算可以复用？

<details><summary>展开核对</summary><p>送回实际选中的 sleeping。新位置会算出自己的查询、键和值，再用查询读取可见位置的信息。前缀的键和值已经按层存在 KV Cache 里，可以直接复用。如果对第一问犹豫，回看解码策略里的贪心与采样；如果对第二问犹豫，回看注意力效率里的 Prefill 与 Decode。</p></details>

### 4. 分主题自测

<details><summary>题 1：BERT 的 MLM 为什么可以看右侧？</summary><p>被选中的输入位置被遮盖或破坏，任务是用周围上下文恢复原词。它不是从没被遮住的目标位置抄答案；实现还需遵守哪些位置参与预测、损失如何构造。</p></details>
<details><summary>题 2：Top-2 路由概率 [0.55,0.25,0.15,0.05]，若重新归一化，前两位权重是多少？</summary><p>保留质量 0.55+0.25=0.8，权重分别为 0.6875 与 0.3125。需要说明具体模型是否采用这套归一化约定，有些实现不重新归一化。</p></details>
<details><summary>题 3：KV 头从 8 减到 2，其他条件不变，缓存减少多少？</summary><p>简化字节公式与 h_kv 成正比，缓存变为原来的 1/4；但端到端速度不保证提高 4 倍。</p></details>
<details><summary>题 4：logits 排序不变，为什么调温度会改变生成？</summary><p>除以正温度不改变大小顺序，却改变 softmax 的概率差距；按分布采样时，各候选被抽中的概率随之变化。</p></details>
<details><summary>题 5：正弦编码的点积只与 m−n 有关，能推出所有注意力也只与距离有关吗？</summary><p>不能。这个性质首先描述位置编码自身；真实注意力还受 token 内容、投影和后续层影响。RoPE 的推导保留了内容向量与相对旋转项，并没有抹掉内容。</p></details>
<details><summary>题 6：用 5 次生成做多数投票，能保证答案更正确吗？</summary><p>不能。多次采样可能共享同一个误解。需要真正的多样性，并配合独立核验；成本通常也会增加。</p></details>

### 7. 哪些表述需要加边界

- 位置编码能算任意位置，不等于模型能可靠外推到任意长度。
- token 效率更高，不等于每个 token 的计算或服务成本更低。
- 专家名字是子网络，不保证训练出人工学科分工。
- RMSNorm 不要求输出中心化；Pre-Norm 不是一种归一化公式。
- 温度为零不等于服务环境中绝对可复现。
- 约束解码只限制形式，不证明事实或业务正确。
- 更多上下文、更多示例、更多采样都需要实测收益与成本。
