## 第二讲导读：从 Transformer 到 LLM

### 这一讲究竟回答什么？

第一讲解释了原始 Transformer 怎样完成翻译。第二讲追问：**怎样把这种架构变成一个可扩展、能生成文本、能够实际部署的大语言模型？**

学习时可以把问题拆成三层：网络如何设计；训练资源怎样分配；输出时怎样选择 token。模型生成的概率与最终选出的文字之间，还有一整套解码策略。

### 先用一句话回顾第一讲

文字被分成 token，再查表变成向量。注意力让不同位置交换信息，FFN 逐位置加工特征，残差与归一化帮助深层训练。原始翻译模型包含编码器和解码器。

```text
文字 → token ID → embedding + 位置
     → 注意力 + FFN + 残差/归一化（重复多层）
     → 上下文表示 → 词表分数 → 概率
```

如果“分数为什么还不是概率”“梯度和参数更新有什么区别”仍不清楚，先读 [第一讲基础工具箱](../../content/collections/cme295/basics.md)。

### 用同一个例子贯穿这一讲

仍然围绕 “A cute teddy bear is reading.”：

- BERT：遮住 cute，根据两侧词预测被遮内容；或者用整句表示判断情感。
- GPT：给 “A cute teddy bear is”，为下一个 token 分配概率。
- MoE：每个 token 在某一层进入不同的少数 FFN 专家。
- RoPE：让查询和键的匹配包含相对位置。
- KV Cache：生成下一个词时复用前文的键和值。
- 解码：在 reading、sleeping 等候选中，根据温度和采样规则选择。
- 提示：让输出满足指定格式、参考明确事实，而不是盲目塞满上下文。

这些例子说明组件职责，不声称真实模型必然按照人类语义把某个 token 路由到“语法专家”或“数学专家”。

## 模型家族：BERT、GPT 与三类架构

### 1. 为什么先讲架构家族？

对应 PDF 第 6–21 页。原始 Transformer 面向“源句 → 译文”。如果只想分类，是否还需要生成器？如果想自由续写，是否还需要独立编码器？这两个问题分别引出 encoder-only 与 decoder-only。

| 家族 | 输入位置的信息范围 | 输出方式 | 例子 |
| --- | --- | --- | --- |
| Encoder-only | 通常双向读取有效输入 | 上下文向量，接任务输出层 | BERT |
| Decoder-only | 标准因果掩码，当前位置读自身及之前 | 预测后续 token | GPT 类 |
| Encoder–Decoder | 编码器双向；解码器因果并读取编码器 | 目标序列逐步生成 | 原始 Transformer、T5 |

它们不是“理解、生成能力”的绝对排名。生成式模型也能做分类；标准 BERT 的训练与接口不直接采用 GPT 式逐 token 生成，但不能因此断言任何 encoder-only 结构都不能生成。

### 2. BERT：先学上下文表示，再适配任务

BERT = Bidirectional Encoder Representations from Transformers，课件介绍 2018 年论文。

**定义**：利用 Transformer 编码器，让一个位置同时参考左右文，得到上下文表示。句首常加入 `[CLS]`，句子边界使用 `[SEP]`。

**为什么需要**：“bank”在河岸和银行语境下需要不同表示。仅查固定词向量表不能直接区分当前含义；编码器使用整段上下文更新表示。

<div class="flow"><span class="chip">[CLS] 这只熊 很 可爱 [SEP]</span><span class="arrow">→ 编码器 →</span><span class="chip">各位置的上下文向量</span><span class="arrow">→ [CLS] 接分类层 →</span><span class="chip">正面 / 负面</span></div>

`[CLS]` 不是天然已经包含准确摘要的魔法符号，它的用途来自训练与下游任务设计。序列标注可以使用每个 token 的向量，不必都挤进 `[CLS]`。

### 3. MLM：遮住一部分，再预测原词

MLM = Masked Language Modeling。它是预训练代理任务：目标不是最终情感分类，而是通过恢复被破坏的词学习语言统计与上下文。

```text
原句：[CLS] A cute teddy bear is reading [SEP]
输入：[CLS] A [MASK] teddy bear is [MASK] [SEP]
目标：          cute                   reading
```

只在被选中用于 MLM 的位置计算恢复目标的损失。例如给 cute 的概率 0.6、reading 的概率 0.5：

```text
L = [−ln(0.6) − ln(0.5)] / 2 ≈ 0.602
```

**补充原论文细节**：经典 BERT 选择约 15% 的 token 作为预测位置，其中约 80% 换 `[MASK]`、10% 换随机 token、10% 保持原样。不是所有被选位置都显示 `[MASK]`，这是缓解训练与实际输入差异的一部分。课件只概括了破坏与恢复过程。

### 4. NSP：两个句子原本相邻吗？

NSP = Next Sentence Prediction。经典 BERT 使用句对输入，让 `[CLS]` 对应表示预测两句是否为文档中的连续句子。

| 输入句对 | 目标（教学构造） |
| --- | --- |
| A：我拿出一本书。B：然后开始阅读。 | 连续 |
| A：我拿出一本书。B：火星是太阳系行星。 | 随机配对 |

注意任务的“连续”标签来自构造数据，不是简单判断两句话看起来是否语义通顺。它也不是预测第二句的每个 token。后续 BERT 变体可能不用 NSP，不能把它当作所有编码器的必要组件。

### 5. 预训练与微调分别改变什么？

- 预训练：用大量文本建立可复用表示，监督信号从文本构造。
- 微调：用任务数据训练输出层，并通常更新全部或部分编码器参数。
- 特征提取：也可冻结编码器，仅训练任务层，这是补充的使用方式。

例子：预训练已学会文本规律；再输入带“正面／负面”标签的评论，学习“哪些表示对应哪一类”。预训练成本与任务微调成本不同，且不保证任何任务只需极少数据。

### 6. GPT：把任务写成下一 token 预测

GPT = Generative Pre-trained Transformer。现代标准 decoder-only 主干没有独立编码器，也移除了原始解码器中的编码器—解码器交叉注意力。

```text
输入：[BOS] A cute teddy bear is
预测：reading / sleeping / ... 的概率
选出 reading 后追加，再预测下一个 token
```

训练通常将目标错开一位：

| 输入位置 | 对应预测目标 |
| --- | --- |
| [BOS] | A |
| A | cute |
| cute | teddy |
| … | … |

模型输出的序列概率可用链式法则写成：

```text
P(x₁,…,xₙ) = ∏ₜ P(xₜ | x₁,…,xₜ₋₁)
```

把分类写成生成任务：`判断情感：这只熊真可爱。情感是：` → 输出“正面”。**不需要每次换任务都重新训练**是使用上的优势，不等于所有 GPT 历史版本都无需微调，也不保证未经指令训练的基座能可靠遵守任何请求。

### 7. 为什么两个能生成的家族仍有区别？

Encoder–Decoder 将输入完整编码，再用另一套因果栈生成输出；Decoder-only 把输入提示与输出接在一条序列中。后者在标准因果注意力下，提示中较早位置看不到后面的提示 token；但生成位置可以读取整个已提供提示。

选择架构还取决于任务、数据与部署，不能把 decoder-only 的普及推成“其他家族已经消失”。

### 理解检查

<details><summary>MLM 与因果下一词预测有什么不同？</summary><p>MLM 从被破坏的输入恢复被选中的位置，常用左右上下文；因果语言模型从左侧上下文预测后续 token。差别包括可见范围、输入构造和损失位置。</p></details>
<details><summary>去掉编码器，交叉注意力应该怎么办？</summary><p>标准 decoder-only 也去掉读取编码器输出的交叉注意力。仅保留因果自注意力、FFN 和相关残差归一化组件，不是把缺失的编码器输出设为零。</p></details>

## 缩放法则：参数、数据与计算预算

### 1. 什么是缩放法则？

对应 PDF 第 22–34 页。缩放法则是实验中观察到的规律：在特定模型、数据和训练设定下，测试损失怎样随模型参数 N、训练 token 数 D 和计算量 C 变化。

常见直觉式表达是 `L ≈ 不可约损失 + A/N^α + B/D^β`。这是教学概括，不是本课程对所有模型宣布一个唯一公式。指数与常数需要由具体实验拟合。

**为什么需要**：训练大模型很贵，不能把每种规模都完整试一遍。小规模实验可以为大规模资源规划提供参考。

### 2. 更多参数、更多数据，各自解决什么？

| 因素 | 直觉 | 不能推导出的结论 |
| --- | --- | --- |
| 参数量 N | 增加可学习容量 | 每个任务都会变好 |
| 数据量 D | 更多训练信号与覆盖 | 垃圾数据也与高质量数据等价 |
| 计算量 C | 允许更多或更大的训练步骤 | 同样 FLOPs 的方案效果必然相同 |

课件第 24 页强调较大模型在相应实验中更有**token 效率**：达到某一损失所需的训练 token 更少。但一个 token 的计算变贵了，所以这不等于算力或能源更省。

例子：小模型需要 1000 个示例，大模型需要 600 个示例达到目标。如果大模型每个示例计算为小模型的 3 倍，总量是 1800 对 1000；样本更省，计算却更多。数字只演示概念。

### 3. FLOPs 与 FLOP/s，差一个时间单位

- FLOPs：浮点运算总次数，像路程。
- FLOP/s（也写 FLOPS）：每秒能做多少次运算，像速度。
- 时间的理想估计：总运算次数 ÷ 每秒运算次数。

```text
总计算量 = 1.2×10¹⁸ FLOPs
有效计算速率 = 2×10¹⁴ FLOP/s
理想时间 = 6000 秒 ≈ 1.67 小时
```

有效速率不是 GPU 宣传的峰值。数据读取、通信、内存和利用率都影响实际时间。字幕“训练失败次数”是 FLOPs 的误译。

### 4. 固定预算下，N 与 D 不能同时无限大

**补充近似**：稠密 Transformer 的训练主计算有时用 `C ≈ 6ND` 估算。它忽略部分注意力、嵌入和系统成本，长序列或特殊结构下偏差会变大。

例如给定 `C = 1.2×10²⁰ FLOPs`：

| 模型参数 N | 由 C≈6ND 算出的 D |
| --- | --- |
| 1×10⁹（1B） | 2×10¹⁰（20B tokens） |
| 2×10⁹（2B） | 1×10¹⁰（10B tokens） |
| 4×10⁹（4B） | 5×10⁹（5B tokens） |

三个方案预算近似相同，但大模型看到的数据更少。真正最优点需要损失实验，不是从乘法表直接选最大 N。

### 5. Chinchilla：模型与数据要配套

课件第 27–28 页介绍 Hoffmann 等 2022 年的计算最优训练研究，给出著名量级直觉：**约 20 个训练 token 对应一个参数**。

```text
D ≈ 20N
70B 参数 × 20 ≈ 1.4T 训练 tokens
```

训练 token 数是训练中处理的数量，需要说明重复与数据口径；不一定等同于独立语料的去重规模。

课件比较更小、数据更多的 Chinchilla 与更大、数据更少的 Gopher，强调当时许多大模型在给定训练预算下“参数太大、训练不足”。

**边界**：20:1 是特定研究背景下的经验结果，不是所有模型的硬规则。长时间服务大量请求时，部署者可能更愿意训练一个更小但训练更充分的模型，以降低长期推理成本。

### 6. 什么叫“大语言模型”？

语言模型给 token 序列分配概率。课程用参数、数据与计算都很大的模型介绍 LLM，并聚焦 decoder-only Transformer。

“大”没有统一精确的参数门槛；LLM 与 decoder-only 并非逻辑同义词。MoE 的总参数和激活参数也要分开，详见[专家路由](../../content/collections/cme295/l2-moe.md)。

### 理解检查

<details><summary>模型 A 用更少训练 token 达到同样损失，就一定更便宜吗？</summary><p>不一定。还需要看每个 token 的计算成本、硬件利用率和推理成本。样本效率、计算效率、服务成本是不同指标。</p></details>
<details><summary>为什么 20:1 不能原样套用所有 MoE 模型？</summary><p>研究中的模型结构、路由、激活计算和数据设定发生变化时，拟合关系也可能改变。课程问答建议先做小规模实验。</p></details>

来源：PDF 第 23–34 页、Kaplan 等 2020、Hoffmann 等 2022；6ND 与预算表为教学补充。


## MoE：每个 Token 选择哪些专家？

### 1. 什么是专家混合？

MoE = Mixture of Experts，PDF 第 35–50 页。

**定义**：让多个可学习子网络作为专家，再由路由器根据输入决定各专家的贡献。稀疏 MoE 每次只执行其中一小部分专家。

**为什么需要**：总参数可以增加，但每个 token 的计算不必按全部专家数增加。注意这是计算上的稀疏，并不意味着保存所有专家的显存、通信、带宽或训练成本都消失。

类比“问数学问题时找少数专家”有助入门，但真实专家是训练出的数值子网络，**不预先指定学科，也不保证最后按学科分工**。

### 2. MoE 通常放在哪里？

现代 Transformer 常把部分层的一个 FFN 换成“路由器＋多位 FFN 专家”，注意力仍负责跨位置交互。

<div class="flow"><span class="chip">注意力后的 token 表示 xₜ</span><span class="arrow">→ Router</span><span class="chip">选择 Top-k 专家</span><span class="arrow">→ 各专家 FFN</span><span class="chip">加权汇总 → 下一层</span></div>

同一句话的不同 token 可以进入不同专家；同一个 token 在不同层也可以选择不同专家。这不是“整次请求永远只选一个模型”。

### 3. Dense 与 Sparse 的区别

```text
路由概率 g(x) = softmax(W_router x)
稀疏选择 S(x) = TopK(g(x))
y = Σᵢ∈S wᵢ(x) Eᵢ(x)
```

Dense 对所有专家求和；Sparse 只计算集合 S 中的专家。被选权重是否重新归一化以及输出缩放，取决于模型实现。

#### 手算一个 Top-2

路由概率 `[0.55,0.25,0.15,0.05]`，前两位被选中。**本教学例子重新归一化**：

```text
保留概率质量 = 0.55 + 0.25 = 0.8
权重 = [0.6875, 0.3125, 0, 0]
E₁(x)=[2,0]，E₂(x)=[0,4]
y=0.6875×[2,0]+0.3125×[0,4]=[1.375,1.25]
```


交互图解「实验：Dense、Top-1 与 Top-2 路由」见[对应章节源文档](../../content/collections/cme295/l2-moe.md)，构建网站后可在该章节操作。


### 4. 总参数与激活参数

假设模型共享部分有 1B 参数，4 个专家各 0.5B，每个 token 只选 2 个，暂不计 Router：

- 总参数：`1 + 4×0.5 = 3B`。
- 每个 token 激活参数的简化估计：`1 + 2×0.5 = 2B`。
- 若两个 token 路由不同，一整个 batch 可能用到全部专家。

激活参数不是完整 FLOPs 计算公式；存储仍要容纳总参数，或通过分布式放置与卸载管理。

### 5. 路由塌缩：为什么“富者愈富”？

一个专家早期略好 → 更常被选 → 更多训练更新 → 更好。其他专家很少被用，计算不均衡，容量也没有充分发挥。

PDF 第 45 页用 Switch Transformer 的辅助损失说明缓解方法：

```text
L_aux = α N Σᵢ fᵢ Pᵢ
fᵢ：路由到专家 i 的 token 比例
Pᵢ：整批 token 对专家 i 的平均路由概率
```

**Top-1 教学例子**：N=4，α=0.01。

| 情况 | f | P | 辅助损失 |
| --- | --- | --- | --- |
| 均衡 | [0.25,0.25,0.25,0.25] | [0.25,0.25,0.25,0.25] | 0.0100 |
| 偏向一位 | [0.75,0.25,0,0] | [0.7,0.2,0.05,0.05] | 0.0230 |

辅助项加在主任务损失之外，以权衡负载与任务效果。它不是强制每个 token 均匀执行所有专家。

#### Top-k 不可导，Router 怎么学？

硬选择的索引不是普通光滑函数。常见训练会把实际分配统计 f 当作不回传梯度的量，沿路由概率、被选输出及辅助目标计算梯度。不同路由算法细节不同，不能说“Top-k 自身可以直接正常求导”。

### 6. 共享专家与细粒度专家

- **共享专家**：每个 token 都执行，用于学习通用变换；路由专家处理额外差异。
- **细粒度专家**：更多、更小的专家，选择若干个组合，扩大组合灵活性。
- **工程代价**：专家间通信、容量限制、溢出和硬件负载都需要解决，k 变小不保证端到端延迟等比例下降。

PDF 第 49–50 页列出的具体模型规模是课件注明日期的示例，不用它作永久榜单，也不把“专家”理解为人工命名角色。

### 理解检查

<details><summary>Top-2 是否意味着整个模型只用两组参数？</summary><p>不是。常见结构保留共享注意力、嵌入、归一化等组件，Top-2 仅指相关 MoE 层选择两位路由专家，可能还要执行共享专家。</p></details>
<details><summary>MoE 与多头注意力相同吗？</summary><p>不同。多头是多组投影并行计算注意力；MoE 路由常用于在多个 FFN 子网络中选择少数执行。不能仅因两者都有多个分支就等同。</p></details>

来源：PDF 第 35–50 页及对应问答；数值为教学补充，辅助公式已对照第 45 页图示核对。


## 位置信息：正弦编码、ALiBi 与 RoPE

### 1. 为什么位置不能省？

对应 PDF 第 51–74 页。基础全连接自注意力的计算没有显式输入顺序标签。交换输入顺序时，结果也会相应交换，而不是自动知道“谁在第一个位置”。这叫置换等变性。

“熊抱着孩子”和“孩子抱着熊”需要不同关系表示。因此要让网络利用位置信息。因果掩码本身也限制可见范围；下面讨论的是明确的位置建模机制。

### 2. 可学习的绝对位置

每个位置编号对应一个可学习向量：`输入 xₘ = token_embedding + position_embedding(m)`。

例子：同一个词在位置 0 与 20 查到相同 token embedding，但加上不同的位置向量后，送入网络的表示不同。

代价是固定位置表的范围。训练只定义了位置 0–511，不能直接查出不存在的第 1000 行。扩展表、插值和继续训练是可能的工程措施，不是逻辑上永远不能变长。

### 3. 正弦编码：快慢不同的“指针”

PDF 第 55–65 页用时钟类比：高频分量快速变化，低频分量慢慢变化。

```text
ωᵢ = 10000^(−2i/d)
PE(m,2i) = sin(mωᵢ)
PE(m,2i+1) = cos(mωᵢ)
```

m 为位置，i 为二维分组索引，d 为偶数维度。以 d=4 为例，两组频率是 1 和 0.01。

| m | PE(m)（近似） |
| --- | --- |
| 0 | [0, 1, 0, 1] |
| 1 | [0.8415, 0.5403, 0.0100, 1.0000] |
| 2 | [0.9093, −0.4161, 0.0200, 0.9998] |

#### 为什么点积涉及相对距离？

利用 `sin a sin b + cos a cos b = cos(a−b)`：

```text
PE(m) · PE(n) = Σᵢ cos((m−n)ωᵢ)
```

只比较位置编码自身时，点积是相对位置差的函数。**这不等于完整 token＋位置经过任意投影后的注意力分数只由距离决定**；token 内容与交叉项仍有影响。

补充直觉：d=4 时，PE(0)·PE(1)≈1.5403，PE(10)·PE(11)也是约 1.5403。平移两个位置，不改变这对编码的点积。

“距离越远一定越不相似”过于绝对，余弦是周期的，可能反弹。公式能为任意新位置求值，也不保证模型对任意长文本都能可靠外推。

### 4. 把位置放进注意力分数

原来的加法位置编码会沿整个网络流动。另一种思路是直接修改注意力里的匹配分数：

```text
score(m,n) = qₘ·kₙ / √dₖ + b(m,n)
```

| 机制 | 如何加入位置 | 关键区别 |
| --- | --- | --- |
| T5 相对位置偏置 | 按头、按相对距离桶学习偏置 | 不是为每个任意距离都单独学习一项 |
| ALiBi | 给因果过去位置加线性距离惩罚 | 斜率按头设计，不用训练绝对位置表 |
| RoPE | 按位置旋转 Q/K，再做点积 | 位置信息进入相对旋转 |

ALiBi 的因果教学写法：`b(m,n)=−sₕ(m−n)`，n≤m、sₕ>0。斜率 0.5 时，当前位置及前 3 个位置偏置依次为 0、−0.5、−1、−1.5。内容得分仍可能克服距离惩罚。

### 5. RoPE：先理解二维旋转

RoPE = Rotary Position Embeddings。字幕里的“繩子”是把 rope 当成普通英文翻译了。

```text
R(φ) = [[cosφ, −sinφ],
        [sinφ,  cosφ]]
R(φ) [x,y]ᵀ = [x cosφ−y sinφ, x sinφ+y cosφ]ᵀ
```

**例子**：向量 [1,0] 旋转 90° 得 [0,1]；长度仍为 1。真实位置角通常以弧度计算，此处用度数只是帮助理解几何。

### 6. 为什么两个旋转只剩相对位置？

以下使用**列向量**约定，与课件图中的行向量记法可能转置，实质相同：

```text
q̃ₘ = R(mθ) qₘ
k̃ₙ = R(nθ) kₙ
q̃ₘᵀ k̃ₙ = qₘᵀ R(mθ)ᵀ R(nθ) kₙ
          = qₘᵀ R((n−m)θ) kₙ
```

因为旋转的转置相当于反向旋转，两个绝对角度相消，剩相对角度。

**手算例子**：θ=30°，m=1、n=3，q=k=[1,0]。

```text
q̃=[cos30°,sin30°]≈[0.8660,0.5]
k̃=[cos90°,sin90°]≈[0,1]
点积≈0.5=cos60°
把 m,n 同时加 5，点积仍≈0.5
```

这里只冻结 q、k 看位置项。真实模型在不同位置上的内容向量也会变化，不意味着所有相距两格的词都得到同一分数。

### 7. 高维版本与长距离的边界

高维 RoPE 把偶数维向量分成二维块，每块按不同频率旋转，例如 [x₀,x₁]、[x₂,x₃]。通常旋转 Q 与 K，V 不作相同旋转。

课件第 74 页讨论长期衰减的相对上界。不要误读成：每个头、每对词的实际注意力权重都随距离单调下降。多频率叠加、内容方向和 softmax 的竞争都在影响结果。

### 理解检查

<details><summary>RoPE 是在 token embedding 上再加一个向量吗？</summary><p>经典 RoPE 的关键是按位置旋转查询和键，让匹配中的位置项体现相对差；与在网络入口直接相加位置向量不同。</p></details>
<details><summary>没有可学习位置表，是不是就能无限扩上下文？</summary><p>不是。公式可求值和模型可靠外推是两回事，还受训练长度、频率设置、推理内存和任务表现限制。</p></details>

来源：PDF 第 52–74 页；已视觉核对第 58、71、73 页公式。数值和 ALiBi 小例子为教学补充。


## 注意力效率：滑动窗口、KV Cache 与 GQA

### 1. 三种优化不要混在一起

对应 PDF 第 75–83 页，以及字幕对 KV Cache 的详细解释。

| 优化 | 改变什么 | 核心收益 |
| --- | --- | --- |
| 滑动窗口 SWA | 一个查询可读取的位置集合 | 少计算远处连接 |
| KV Cache | 生成时是否重算历史键和值 | 复用已经算好的结果 |
| GQA / MQA | 查询头共享几组 K/V | 减少缓存与键值投影成本 |

它们可以组合，但一个并不能自动推出另外两个。

### 2. 滑动窗口：每层只看近邻

SWA = Sliding Window Attention。例如每个位置只能读自己和左侧 2 个位置。

```text
位置： 1 2 3 4 5 6
查询6：× × × ✓ ✓ ✓
查询5：× × ✓ ✓ ✓ ×（未来不可见）
```

**为什么仍可传播较远信息**？第 6 个位置这一层读到第 4 个位置，而第 4 个位置上一层已经读取更早输入。经过多层可以间接扩大感受野。


交互图解「实验：每层只能读自己和左侧 2 个位置」见[对应章节源文档](../../content/collections/cme295/l2-attention-cache.md)，构建网站后可在该章节操作。


若每层向左读 r 个额外位置，L 层后理论可达左侧 Lr 个位置，连自身范围约 Lr+1。这里 r=2，1、2、3 层对第 6 个位置的覆盖分别是 3、5、6 个输入位置。

**边界**：存在信息路径不等于每条远处细节都被保存。固定窗口会改变模型计算结构，需要相应训练或适配，不是把任意全局模型窗口截短就保证效果不变。

课件先介绍 Longformer 的稀疏模式，再介绍局部／全局层混合与 Mistral 的窗口例子。Longformer 的全局 token 与局部窗口是一类设计，不能说所有局部注意力模型都有全局 token。

### 3. 复杂度怎样变化？

全注意力分数规模约 n×n；窗口宽度 w 固定时，只保留约 n×w 个连接。因此注意力打分这一部分由 O(n²) 降到 O(nw)。

这个比较省略特征维度，也不代表整个模型只有 O(nw) 成本，FFN、投影和层数仍存在。

### 4. KV Cache：生成时记住已经算过的 K/V

标准因果 decoder-only 中，旧位置不能看见新位置。因此在权重固定、位置规则和前缀一致时，生成新词不会改变旧前缀的位置表示。

```text
Prefill：把提示中的所有位置处理一遍，保存每层 K、V
Decode：计算新位置的 Q、K、V
        把新 K、V 追加缓存，用新 Q 读取历史 K、V
        输出下一个 token 的分布
```

例如已有 “A teddy bear”，模型预测出 is；处理新输入 is 时，只需为这个位置计算当前层的新 Q/K/V，前面 A、teddy、bear 的 K/V 可复用。

Q 在当前查询完成后通常不用于后续 token 的注意力，因此通常不缓存所有历史 Q。缓存仍然要**每层分别存**。

#### 这与模型的“长期记忆”相同吗？

不是。KV Cache 是推理中的数值中间结果，与保存聊天摘要、检索知识库或更新模型参数不同。前缀改变或权重更新后，旧缓存可能失效。

KV Cache 的讨论主要针对逐 token 推理；训练通常并行处理已知序列，不采用同样的解码缓存流程。

### 5. MHA、GQA、MQA：保留 Q 头，减少 K/V 头

设查询头数 h_q=8：

| 方式 | K/V 头数 h_kv | 共享关系 |
| --- | --- | --- |
| MHA | 8 | 每个查询头自己的 K/V |
| GQA | 2 | 每 4 个查询头共享一组 K/V |
| MQA | 1 | 8 个查询头共享一组 K/V |

<div class="flow"><span class="chip">Q₁ Q₂ Q₃ Q₄ → K₁ / V₁</span><span class="chip">Q₅ Q₆ Q₇ Q₈ → K₂ / V₂</span></div>

GQA 是中间折中；MHA 和 MQA 是共享组数的两个端点。减少 K/V 头不意味着所有 Q 头输出相同，每个 Q 的内容仍不同。

### 6. 真正算一次缓存占用

常规未量化 K/V 缓存的简化估计：

```text
bytes = 2 × B × n × L × h_kv × d_head × bytes_per_value
        ↑K和V  batch 长度 层数 KV头 每头维度 每个数值字节
```

假设 B=1、n=4096、L=32、d_head=128、每值2字节：

| 模式 | h_kv | 字节 | 二进制单位 |
| --- | --- | --- | --- |
| MHA | 8 | 536,870,912 | 512 MiB |
| GQA | 2 | 134,217,728 | 128 MiB |
| MQA | 1 | 67,108,864 | 64 MiB |

只改 K/V 头数，缓存由 512 MiB 降到 128 MiB 是 4 倍压缩。这里只算 K/V，不包括权重、工作区、分配开销、分页碎片等。多个请求或更长上下文会继续放大占用。

### 理解检查

<details><summary>用了 KV Cache，每步还要读取历史吗？</summary><p>通常仍要用新 Q 与可见历史 K 比较，再汇总历史 V。缓存省的是重复生成历史 K/V 等计算，不是免掉所有历史读取。</p></details>
<details><summary>GQA 能保证端到端吞吐提高 4 倍吗？</summary><p>不能。缓存缩小的倍数可从公式计算，但实际速度受其他算子、带宽、batch、硬件与内核实现影响。</p></details>

来源：PDF 第 75–83 页、字幕 KV Cache 解释。缓存公式、内存例子和滑窗可达图是教学补充；第 82 页已视觉核对。


## 归一化：Pre-Norm 与 RMSNorm

### 1. 先分开两个问题

PDF 第 84–88 页讨论两条彼此独立的变化：

1. **位置**：归一化在残差相加之前还是之后？Pre-Norm / Post-Norm。
2. **公式**：减均值再缩放，还是只按均方根缩放？LayerNorm / RMSNorm。

“Pre-Norm 就是 RMSNorm”是错误的。一个讨论放置顺序，一个讨论具体算子。

### 2. Post-Norm 与 Pre-Norm

f 是注意力或 FFN 子层，省略 Dropout：

```text
Post-Norm：y = Norm(x + f(x))
Pre-Norm： y = x + f(Norm(x))
```

<div class="flow"><span class="chip">Post：x → f → 与 x 相加 → Norm</span><span class="chip">Pre：x → Norm → f → 与 x 相加</span></div>

**为什么 Pre-Norm 经常用于深层模型**？它让残差主通路上的 x 不必在每个子层后穿过归一化，能改善梯度传递与训练稳定性。

但“梯度永远无损”“从此不需要 warmup”都不是保证。初始化、优化器、训练精度、深度以及其他结构仍影响训练。

### 3. LayerNorm：减均值，再按标准差缩放

对一个 token 的 d 维表示 x：

```text
μ = mean(x)
σ² = mean((x−μ)²)
LN(x) = γ ⊙ (x−μ)/sqrt(σ²+ε) + β
```

γ、β 通常是 d 维可学习向量；⊙ 表示逐项相乘。这里沿特征维计算，不把不同句子的所有位置混在一起。

#### 用 [1,3] 算一遍

为了手算先省略很小的 ε，取 γ=[1,1]、β=[0,0]：

```text
μ=(1+3)/2=2
σ²=[(1−2)²+(3−2)²]/2=1
LN([1,3])=[−1,1]
```

注意力在各位置之间混合信息，归一化是在每个位置自己的特征中控制尺度，职责不同。

### 4. RMSNorm：不减均值，按均方根缩放

```text
RMS(x) = sqrt(mean(x²))
RMSNorm(x) = γ ⊙ x / sqrt(mean(x²)+ε)
```

常见 RMSNorm 不包含与 LayerNorm 相同的均值中心化与 β 偏置，但具体实现可能有细节差异。

同样令 γ=[1,1]，暂略 ε：

```text
RMS([1,3])=sqrt((1²+3²)/2)=sqrt(5)≈2.2361
RMSNorm([1,3])≈[0.4472,1.3416]
```

| 对比 | LayerNorm | RMSNorm |
| --- | --- | --- |
| 减均值？ | 是 | 否 |
| 归一化尺度 | 标准差 | 均方根 |
| 示例输出 | [−1,1] | [0.4472,1.3416] |
| 输出均值必为 0？ | 加可学习仿射后不保证 | 本来就不要求 |

RMSNorm 保留非零均值也没关系，它不是为了让所有值正负对称，而是采用更简化的缩放机制。是否更快要结合内核和硬件，不能只看公式就保证速度倍数。

### 5. 小心残差相加的位置

用 x=[1,3]、f(u)=2u 这个**纯教学子层**：

- Post-LN：`LN(x+2x)=LN([3,9])=[−1,1]`。
- Pre-LN：`x+2LN(x)=[1,3]+[−2,2]=[−1,5]`。

两个结果不同，归一化和子层一般不能任意交换顺序。真实子层更复杂，不是把一层搬动一下就保持原模型输出。

### 理解检查

<details><summary>RMSNorm 是否把 token 的每个数都变成 1？</summary><p>不是。它统一除以一个尺度，保留分量之间的比例，再使用可学习 γ。示例 [1,3] 的结果仍保持 1:3 的比例。</p></details>
<details><summary>Pre-Norm 与残差是不是重复功能？</summary><p>不是。残差提供 x 的直接通路，Pre-Norm 规定归一化在子层支路中何处执行。两者协同影响优化。</p></details>

来源：PDF 第 84–88 页及字幕，已视觉核对 85–87 页。数值例子省略 ε 的影响并明确固定 γ、β，为教学补充。


## 解码策略：贪心、Beam、温度与约束生成

### 1. 从预测到选择，还差一步

对应 PDF 第 89–123 页。模型把隐藏表示投影成词表 logits，再经 softmax 得到概率；**解码策略决定如何利用概率选择下一个 token**。

```text
上下文 → 网络 → logits z → 概率 p → 选择 token → 追加到上下文 → 重复
```

这与训练时最小化交叉熵不同：推理时不是对下一词标签反向训练，而是在固定模型下做选择。

### 2. 贪心：每次挑当前最高概率

Greedy decoding 选择 `argmax p`。优点是简单；缺点是当前最佳一步不等于整条序列概率最高。

#### 两步完整反例

第一步 A 的概率 0.6、B 为 0.4。第二步条件分布：

| 前缀 | 下个 X | 下个 Y | 对应最高两步联合概率 |
| --- | --- | --- | --- |
| A | 0.51 | 0.49 | P(AX)=0.6×0.51=0.306 |
| B | 0.99 | 0.01 | P(BX)=0.4×0.99=0.396 |

贪心先选 A，再选 X，得到 AX；但 BX 更可能。每行概率都加到 1。这个例子固定两步结束，不涉及不同长度比较。

### 3. Beam search：保留多个前缀

Beam width=2：先保留 A 和 B，再扩展四条候选：

```text
AX: 0.306    AY: 0.294
BX: 0.396    BY: 0.004
保留 BX 与 AX
```

通常以对数概率相加计算，避免长序列乘积下溢。实际搜索还要处理 `[EOS]`、长度惩罚和终止条件。

Beam 是受限搜索，不保证全局最优；不同长度概率也不能天真比较。更大的 beam 可能更慢，且最高似然不等于最有用、最真实或最有创意的回答。

### 4. 采样：按概率抽取，不总取第一名

若候选分布 `[0.40,0.25,0.20,0.10,0.05]`，第一名长期平均约被选 40%，不是每次都选它。真实单次抽样可能选到任何非零候选。

随机性适合需要多样性的任务；对可重复抽取、评测等任务可以偏好确定性策略。不存在“所有场景随机一定更好”。

### 5. Top-k 与 Top-p

#### Top-k：固定保留几个

k=2，保留前两名，总概率 0.65，重新归一化：

```text
[0.40/0.65, 0.25/0.65] ≈ [0.6154,0.3846]
```

然后从这两个候选中抽样。Top-k 不是强制每 k 步换一个词。

#### Top-p：固定保留多少概率质量

按概率从大到小，取累计概率**第一次达到或超过阈值**的最小前缀，再归一化。

| p 阈值 | 保留原概率 | 原质量 | 新分布 |
| --- | --- | --- | --- |
| 0.60 | [0.40,0.25] | 0.65 | [0.6154,0.3846] |
| 0.80 | [0.40,0.25,0.20] | 0.85 | [0.4706,0.2941,0.2353] |
| 0.90 | [0.40,0.25,0.20,0.10] | 0.95 | [0.4211,0.2632,0.2105,0.1053] |

p=0.8 不意味着只保留原概率小于 0.8 的词，也不保证留下固定个数。Top-k 与 Top-p 同时使用时，顺序与实现约定需要查具体服务。

### 6. 温度：调分布形状

```text
pᵢ(T) = exp(zᵢ/T) / Σⱼ exp(zⱼ/T)，T>0
```

- 低 T：更尖，偏向高分候选。
- T=1：原 softmax。
- 高 T：更平，较低分候选更容易出现。


交互图解「实验：同样的 logits [2,1,0,−1]，只改变温度」见[对应章节源文档](../../content/collections/cme295/l2-decoding.md)，构建网站后可在该章节操作。


<strong>重要：</strong>任何有限正温度下，如果仍做采样，就不是严格的贪心。T=0 时公式除零没有定义，API 中的 `temperature=0` 通常是约定进入贪心或近似确定性模式。T→0⁺ 在最大分唯一时集中到最大项；若并列还要看 tie-break 规则。

Temperature 改变相对概率，Top-k / Top-p 截断候选。它们改变输出，不会把权重重新训练，也不保证更低温度回答更真实。

### 7. 为什么温度为零仍可能不完全复现？

PDF 第 115–116 页讨论服务中的非确定性。权重、输入和理论运算固定，不代表每个硬件和批处理配置的浮点路径完全一致。

```text
(10¹⁶ + (−10¹⁶)) + 1 = 1
10¹⁶ + ((−10¹⁶) + 1) = 0  （常见 IEEE 754 双精度下）
```

浮点加法不严格满足结合律。内核、批处理、规约顺序和数值精度的微小差异，可能在候选分数非常接近时改变 argmax。还要固定模型版本、提示模板、工具结果、种子与运行环境，不能只设 T=0 就声称绝对复现。

### 8. Guided decoding：限制哪些下一 token 合法

**定义**：生成过程中用语法或 Schema 检查当前前缀，只允许合法续写。可以把不合法候选分数设为 −∞，再在合法集合中归一化与选择。

例如目标是 `{"age":33}`：

```text
当前前缀：{"age":
若 Schema 要求 age 为整数，下一步不能继续一个普通对象键
合法续写需要组成一个整数，然后闭合对象
```

这些是字符级直觉示意。实际 token 可能包含多个字符，约束实现需要处理 token 到语法状态的转换，不能把一个 token 永远当作一个字符。

<div class="flow"><span class="chip">模型 logits</span><span class="arrow">＋ 语法状态 →</span><span class="chip">屏蔽不合法候选</span><span class="arrow">→ 选择 →</span><span class="chip">更新语法状态</span></div>

**格式合法不等于事实正确**。符合 Schema 的 age 仍可能是编造的；还需要字段校验、来源核对与业务验证。截断、拒答和服务支持范围也可能造成生成失败，不能简单承诺任何情况下 100% 成功。

### 理解检查

<details><summary>Top-p=0.8 时为什么累计质量可能是 0.85？</summary><p>因为候选 token 不可拆成“半个候选”。加入第三项后累计从 0.65 跳到 0.85，首次达到阈值就停，再把保留集合归一化。</p></details>
<details><summary>温度调低是否会改变最可能 token 的排序？</summary><p>同一组有限 logits 除以正 T 不改变大小顺序，但改变概率差距。采样、其他处理器、舍入与并列情况可能影响实际输出。</p></details>

来源：PDF 第 89–123 页；已视觉核对第 108、112 页。Beam 反例、采样分布和浮点例子为教学补充。


## 上下文、提示与推理：给什么、怎么给？

### 1. 上下文不只是你输入的一句话

对应 PDF 第 124–137 页。每次预测后，新生成 token 会追加到序列，再用于下次预测。因此可用上下文通常包含：系统说明、历史消息、用户问题、工具结果以及已生成的内容。

**上下文窗口**是服务或模型允许处理的长度边界；**最大输出**是本次或产品另行规定的生成上限。具体 API 对输入、输出、缓存和推理 token 的口径可能不同，要查版本说明。

#### 算一次预算

教学假设：总窗口 8192 token，所有输出都计入这个总预算，且独立输出上限 2048：

```text
系统与模板 500
历史与资料 3500
用户问题   1000
输入合计   5000
总窗口剩余 8192−5000=3192
实际允许输出 ≤ min(3192,2048)=2048
```

不是“用户文字还没达到 8192，就肯定能再输出 8192”。工具描述、模板或服务额外 token 也可能占位。

### 2. Token 与页数，只能粗估

课件第 129–130 页用英文经验：1 token≈0.75 个英文词，一页约400词，因此约533 token，课堂取整为500左右。

这个估计依赖字体、语言、排版与 tokenizer。中文、代码和表格没有固定“一个字就是一个 token”的换算。成本、窗口与输出长度应使用目标模型分词器实际统计。

课件第 126–128 页给出的产品规格属于材料注明日期的快照，不代表所有模型具有相同窗口或输出限制。

### 3. 上下文更长，为什么可能反而更难？

Context rot 指输入变长、相关信息被噪声稀释后，模型表现可能下降的现象。Needle-in-a-Haystack 测试把目标事实放在长上下文不同位置，再检查能否找回。

```text
任务：找到熊 A 的年龄
相关事实：熊 A 今年 4 岁
噪声：几百页与任务无关的其他玩具记录
```

“模型能接收这么多 token”是容量约束，不等于“能可靠利用每一段信息”。但不同任务与模型的表现不同，不应把任何长输入都断言为必然更差。

可行做法：先明确任务，检索相关资料，删掉无关重复，保留关键条件，必要时摘要。压缩也会丢信息，完成后应核对是否仍能回答任务。

### 4. ICL：通过上下文示例适配任务

ICL = In-Context Learning。模型根据当前输入中的说明或例子调整回答，**不更新模型权重**，不同于微调。

#### Zero-shot：只给任务与必要事实

```text
已知：熊 A 在 2024 年是 4 岁。
问题：2025 年熊 A 是几岁？
要求：只输出年龄数字。
```

期望输出 5。这里仍然要提供足够事实；zero-shot 指没有任务示范，不是“不许给任何背景”。

#### Few-shot：示范输入与输出

```text
例子：熊 B 在 2024 年是 3 岁 → 2025 年是 4 岁。
例子：熊 C 在 2024 年是 6 岁 → 2025 年是 7 岁。
已知：熊 A 在 2024 年是 4 岁 → 2025 年是？
```

示例展示“年龄增加一年”的任务规则和答案格式。用与查询过于相似的泄漏答案并不构成有意义的评测。

| 方式 | 改参数？ | 主要成本 | 风险 |
| --- | --- | --- | --- |
| Zero-shot | 否 | 提示与生成 | 说明不充分 |
| Few-shot | 否 | 额外示例 token | 示例偏差、格式过拟合 |
| 微调 | 是 | 训练与权重维护 | 数据与训练偏差 |

示例不是越多越好，也不能说现代推理模型永远不需要示例。应在固定评测集上比较。

### 5. CoT：分步示范与中间计算

CoT = Chain-of-Thought。课件介绍通过分步示例改善多步任务表现的历史思路。这里用**可验证的简短算式**展示教学过程：

```text
题目：2024 年 4 岁，2025 年几岁？
年份差：2025−2024=1
答案：4+1=5 岁
```

原字幕和课件出现“现在”“明年”以及不同年份，容易产生歧义。统一固定 2024→2025，避免把随日期变化的事实混进计算。

这类中间计算帮助检查，但模型生成的解释未必忠实反映其内部因果过程，也不是正确性的证明。实际使用推理模型时，可要求简短理由、引用与结果验证，不必强求完整内部思维链。

### 6. Self-consistency：多条采样，聚合答案

**定义**：生成多个候选求解结果，按最终答案聚合，例如多数投票。它是推理时多花计算换表现的策略，不是训练新参数。

教学采样答案：`[5,5,4,5,4]`，答案 5 获 3/5 票，选 5。

<div class="flow"><span class="chip">同一问题</span><span class="arrow">→ 多次采样 →</span><span class="chip">5 / 5 / 4 / 5 / 4</span><span class="arrow">→ 聚合 →</span><span class="chip">多数答案：5</span></div>

**票数比例不是校准后的正确概率**。如果样本高度相关或模型存在系统性误解，多数也会错。需要统一答案格式、处理并列，结合独立计算或事实核对。

### 7. 把提示与解码、模型训练分开

- 提示：改变模型看到的上下文。
- 温度与采样：改变从当前输出分布中如何选择。
- 微调：改变模型参数。
- Self-consistency：增加采样次数并聚合。
- Guided decoding：限制合法输出形式。

例如“给年龄问题加两个例子”不是微调；“要求 JSON”也不是严格语法约束本身。不同层面的工具可以组合，但需要分别验证效果与成本。

### 理解检查

<details><summary>few-shot 为什么会增加延迟和费用？</summary><p>示例增加输入 token，预填充计算及存储可能增加。缓存命中、服务计费和生成长度还会影响实际成本，不应直接按示例个数推断固定倍数。</p></details>
<details><summary>Self-consistency 得到 5 的票数是 60%，能说答案有 60% 概率正确吗？</summary><p>不能。这只是该采样集合中的频率；样本独立性、模型偏差与解码策略会影响它，需要另外校准或验证。</p></details>

来源：PDF 第 124–137 页及字幕，已视觉核对第 125、137 页。窗口预算与固定年份例子为教学补充。


## 第二讲复习：一张对照表串起 LLM

### 1. 一个请求怎样经过本讲的组件？

假设给 decoder-only 模型提示：“熊 A 在 2024 年 4 岁，请输出 2025 年年龄的 JSON。”

1. 提示与模板分词，检查输入和输出预算。
2. token 进入模型；各层用位置机制（例如 RoPE）构造带相对位置信息的匹配。
3. 注意力按允许范围读取上下文，FFN 或 MoE 处理每个位置。
4. Pre-Norm、RMSNorm 等组件按具体架构执行，不是推理时临时选择的按钮。
5. 输出隐藏表示投影为 logits，温度和候选规则调整选择方式。
6. 若支持约束解码，屏蔽不符合 JSON／Schema 的续写。
7. 新 token 追加到上下文；KV Cache 复用历史结果。
8. 到结束条件停止，再检查 age 是否等于 5，而不只检查 JSON 可解析。

这是教学组合例子，不表示所有模型都使用 MoE、GQA 或同一套归一化。

### 2. 六条主线总表

| 课件章节 | 记住的核心 | 易错点 |
| --- | --- | --- |
| 模型家族 | 编码表示或因果预测；输入可见范围不同 | “decoder-only 不理解输入” |
| 缩放法则 | 参数、数据、训练与推理预算共同影响方案 | “模型更大一定省钱” |
| 专家路由 | 每个 token 可只执行少数专家 | “总参数等于每次激活参数” |
| 架构优化 | 位置、访问范围、缓存、共享头、归一化各有职责 | “GQA 就是缩短窗口” |
| 解码 | logits 之后还要选择候选 | “Top-p=0.8 就是保留 80% 个词” |
| 提示与推理 | 不改参数地组织上下文、示例、采样聚合 | “解释流畅就是内部推理真实且正确” |

### 3. 自测与解析

<details><summary>题 1：BERT 的 MLM 为什么可以看右侧？</summary><p>输入被选位置被遮盖或破坏，任务是利用周围上下文恢复原词。它不是从未遮住的目标位置复制答案；实现还需要遵守预测位置与损失构造。</p></details>
<details><summary>题 2：Top-2 路由概率 [0.55,0.25,0.15,0.05]，若重新归一化，前两位权重是多少？</summary><p>保留质量 0.8，权重分别 0.6875 与 0.3125。应明确具体模型是否采用这套归一化约定。</p></details>
<details><summary>题 3：KV 头从 8 减到 2，其他条件不变，缓存减少多少？</summary><p>简化字节公式与 h_kv 成正比，缓存变成原来的 1/4；端到端速度不保证提高 4 倍。</p></details>
<details><summary>题 4：logits 排序不变，为何调温度会改变生成？</summary><p>除以正温度不改变排序，却改变 softmax 概率差距；按分布采样时，候选被抽中的概率变化。</p></details>
<details><summary>题 5：正弦编码的点积只与 m−n 有关，能说所有注意力也只与距离有关吗？</summary><p>不能。这个性质首先是 PE 自身的点积；实际 token 内容、投影与其他层还会影响分数。RoPE 推导保留内容向量和相对旋转项，并不是抹掉内容。</p></details>
<details><summary>题 6：用 5 次生成多数投票，能保证答案更正确吗？</summary><p>不能保证。多个答案可能共享同一误解，应使用有意义的多样性并加入独立核验；成本通常也会增加。</p></details>

### 5. 哪些表述需要加边界？

- 可计算更长位置的编码，不等于模型能可靠外推到无限上下文。
- token 效率更好，不等于每个 token 的计算或服务成本更低。
- 专家名是子网络，不保证训练出人工学科分工。
- RMSNorm 不要求输出中心化，Pre-Norm 也不是一种归一化公式。
- 温度为零不等于服务环境中绝对可复现。
- 约束解码限制形式，不证明事实或业务正确。
- 更多上下文、更多示例、更多采样均需要实测收益与成本。
