## 预训练：Teacher forcing、交叉熵与 BPB

### 1. 预训练究竟学什么？

PDF 第 8–22 页。预训练用大量文本和代码建立可复用的语言模型，而不是为每个任务都从头训练一套参数。

**下一 token 预测**要求：给定已有前缀，给真实的下一 token 分配高概率。语法、常识、代码模式等可能在完成这个任务时被学到，但不等于模型获取了一套可保证真实、完整的知识库。

### 2. Teacher forcing 是什么？

**定义：** 训练时使用数据中真实的前一个 token 作为后续预测的输入，即使模型刚才预测错了，也不把那个错误预测接回去。

```text
原始数据：[BOS] A teddy bear [EOS]
网络输入：[BOS] A teddy bear
训练目标：  A  teddy bear [EOS]
```

例如 A 后模型更偏向 cute，但训练文本是 teddy。后续位置仍输入真实的 teddy，教模型在这个真实前缀上预测 bear。

<div class="flow"><span class="chip">真实前缀</span><span class="arrow">→ 固定本次参数前向 →</span><span class="chip">各位置的词表概率</span><span class="arrow">→ 对照下一 token →</span><span class="chip">损失、反向、更新</span></div>

“forcing”不表示跳过学习或直接把正确答案写入权重，模型仍然要根据损失算梯度。

### 3. 全句已经给进去了，为什么没偷看答案？

因果掩码确保位置 t 的表示只能读取位置 ≤t，再用它预测位置 t+1。因此可以一次输入整条训练序列、并行计算多个位置的损失。

| 当前输入位置 | 可读取 | 预测目标 |
| --- | --- | --- |
| [BOS] | [BOS] | A |
| A | [BOS], A | teddy |
| teddy | [BOS], A, teddy | bear |
| bear | [BOS], A, teddy, bear | [EOS] |

**训练／推理差异：** 推理把模型自己选出的 token 接回输入，训练主要使用真实前缀。这个分布差异常称为 exposure bias 的相关问题，后续基于模型采样的训练试图减少某些失配，但并不自动消除所有误差。

### 4. 交叉熵从哪里来？

设序列为 x₁,…,x_T，模型参数为 θ。

```text
序列概率：Pθ(x₁,…,x_T)=∏ₜ Pθ(xₜ | x_<t)
最大化概率 ↔ 最大化 Σₜ ln Pθ(xₜ | x_<t)
训练常用最小化：L_CE=−(1/T) Σₜ ln Pθ(xₜ | x_<t)
```

对数把连乘变连加，避免长串小概率连乘下溢；加负号是从最大化转成最小化；除以活动 token 数控制规模。

实际计算用稳定的 log-softmax 或等价实现，不是先真的算出可能下溢的整句乘积再取 log。

#### 手算一个序列

假设给四个真实目标 token 的条件概率是 `[0.5,0.25,0.8,0.5]`：

```text
序列概率=0.5×0.25×0.8×0.5=0.05
负对数似然总量=−ln(0.05)≈2.9957 nats
平均损失=2.9957/4≈0.7489 nats/token
```

这些数字来自不同前缀下的目标项，不要求它们彼此相加为 1；每个位置自己的完整词表分布才应归一化。

### 5. Bits Per Byte：换一个分母比较

不同 tokenizer 把同一段文本切成不同数量的 token，直接比较 nats/token 容易混淆。

```text
BPB = L_CE × T / B / ln(2)
T：计分 token 数；B：对应原始文本的 byte 数
```

若上例覆盖 10 bytes：`BPB≈0.7489×4/10/ln2≈0.4322 bits/byte`。

若另一个 tokenizer 用 2 个 token 表示同样文本，且整段负对数似然恰好也是 2.9957：它的平均 token 损失是 1.4979，但 BPB 仍约 0.4322。这里特意固定整段似然，只展示归一化差异。

**边界：** BPB 统一计量单位，不让模型分布、语料预处理、UTF-8 字节口径或评测边界自动相同。它也不是“每个 token 真正占多少存储位”的直接实测。

### 6. 什么时候算哪些位置？

padding 等位置通常不参与训练目标，平均分母是有效计分数。文档边界、BOS/EOS 和跨文档注意力是否隔离，取决于训练设置。

下一节会讨论语料怎样拼接或装箱；SFT 则进一步规定回答部分的 loss mask，详见 [SFT](../../content/collections/cme295/l3-sft.md)。

## 数据、Mid-training 与长上下文

### 1. 训练目标一样，数据为什么仍决定效果？

PDF 第 23–40 页。下一词损失只告诉模型匹配训练分布；如果语料本身包含重复、错误、缺少某种语言或代码，模型不会因为公式正确就自动补齐这些问题。

课件列举网页、知识文本、代码、数学和科学数据，强调筛选与配比是实际训练的重要工作。

<div class="flow"><span class="chip">原始网页／代码／文档</span><span class="arrow">→ 清洗、去重、质量筛选 →</span><span class="chip">按来源与任务混合</span><span class="arrow">→ 分词、打包 →</span><span class="chip">训练与独立评估</span></div>

过滤、数据权利、敏感信息处理与污染控制是数据流程问题。本站不把互联网内容多视为可以随意收集或发布的许可。

### 2. 混合比例怎样影响训练？

假设总训练预算 100 万 token，教学比例设为网页50%、代码30%、数学20%：分别是50万、30万、20万。这里按 token，不是按文件数。

若代码文档平均长度是网页的两倍，“30% 文件来自代码”并不等于“30% token 来自代码”。混合比例必须写清分母。

课件提到 RegMix：用不同配比训练小模型，再依据结果预测较好的大规模混合方案；DataComp-LM 尝试控制架构变量来比较训练数据。它们说明需要实验，不提供一套适合所有模型的固定比例。

### 3. 重复数据是否永远没用？

课件引用数据受限研究，指出有限重复可能仍有价值。应把它理解为研究设定下的结果，**不是“所有语料重复四遍一定最好”**。

- 高质量资料重复几次可能继续提供训练信号。
- 相同数据反复看不等于新增独立知识，也可能过拟合。
- 验证集必须独立，不能把重复训练材料拿来证明泛化。
- 处理 token 总数、独立 token 量、epoch 数是不同指标。

### 4. Mid-training 是什么？

**定义：** 在大规模预训练之后，用更针对目标能力的数据继续训练的一种阶段划分。课件用它介绍高质量数学、代码和长上下文能力的加强，常仍采用下一 token 目标。

它没有全行业统一精确定义。不要把“mid-training 数据一定全部无指令”“所有模型一定有独立中期阶段”当成必要条件。

| 阶段 | 重点 | 教学例子 |
| --- | --- | --- |
| 预训练 | 广泛语言与代码模式 | 多来源文本 |
| Mid-training | 强化某类能力或长度 | 长代码修改、数学资料 |
| SFT | 模仿期望输入输出行为 | 给用户问题输出指定回答 |

### 5. 长上下文为什么还要训练？

第二讲说 RoPE 可以为新位置计算角度，但模型在短序列训练时没见过所有长距离模式。**公式能算出 ≠ 模型会可靠使用。**

课件介绍 RoPE 扩展（例如 YaRN）与课程式长度训练：4K→32K→128K→1M。这是方法与量级示意，不代表每个模型固定按这些长度训练。

YaRN 等方法会调整位置频率或尺度规则并配合适当训练。它们有具体设计细节，不能缩成“把所有角度随意除一个数就完全等价”。推理需要使用与训练/适配一致的位置设置。

### 6. “长”本身不是有效监督

一个长文件如果末尾句子不依赖开头事实，未必教会长距离检索。

**教学样本：** 第一段明确“Polar 的洗护标签允许烘干”，在长文后部提出“哪只玩偶能烘干？”；加入可区分的其他标签，并验证答案必须利用前面的事实。

需要同时控制位置、多跳关系、干扰项和数据真实性，避免只是重复关键词就能猜答案。

#### 计算为何更贵？

如果纯全注意力长度由4096增加到32768，为8倍长度，分数连接数量变成64倍。由4096到131072是32倍长度，连接数约1024倍。

这只比较注意力连接数量，不是实际端到端训练费用必然同比增长；内存算法、稀疏模式、并行与其他算子会影响结果。

### 7. 知识截止日期与知识编辑

课件讨论成本、知识时效、难修改与文本复现风险。知识截止日期通常反映训练资料和产品说明的时间范围，不能保证此前每个事实都知道，也不意味着后来信息绝对无法通过提示或检索获得。

外部检索补充当前资料，并不等于权重已经更新。SFT 或继续预训练可以改变行为与知识表现，但也不等于精确编辑一条数据库记录。

## SFT：教模型怎样回答，损失算在哪里？

### 1. SFT 是什么？

SFT = Supervised Fine-Tuning，PDF 第 41–52 页。

**定义：** 给模型示范“输入是什么、期望输出是什么”，通过监督训练更新权重，使其更符合目标行为。使用指令与回答数据进行 SFT，常称为 instruction tuning。

**为什么需要：** 预训练擅长延续文本分布，但用户通常希望模型直接遵守请求、回答问题，而不是继续写一篇相邻主题文章。

例子：输入“用一句话解释什么是梯度”，目标是简洁解释；不是只添加更多带“梯度”这个词的百科段落。

### 2. 与预训练的共同点和不同点

共同点是仍常使用 teacher forcing 与下一 token 交叉熵。不同点是条件与计分位置：

```text
L_SFT = −(1/T_answer) Σₜ ln Pθ(yₜ | x, y_<t)
x：完整提示；y：期望回答
```

通常把提示与回答串接送入网络，**对回答位置的目标项计分**。课件这里讨论的是 response-only loss；其他工程配方也可能对不同角色或部分提示计分，需说明自己的约定。

### 3. 一个连续的教学例子

把提示概念性切成“解释／熊／的年龄”，回答切成“5／岁／[EOS]”。为了只看损失位置，直接给定模型对真实目标的条件概率：

| 目标 token | 概率 | 属于提示还是回答 |
| --- | --- | --- |
| 解释 | 0.10 | 提示 |
| 熊 | 0.20 | 提示 |
| 的年龄 | 0.25 | 提示 |
| 5 | 0.50 | 回答 |
| 岁 | 0.80 | 回答 |
| [EOS] | 0.90 | 回答 |

这是人为分词和概率，不是实际 tokenizer 输出；这些目标概率来自不同预测位置，不要求这一列相加等于1。


交互图解（l3-loss-mask）见[对应章节源文档](../../content/collections/cme295/l3-sft.md)，构建网站后可在该章节操作。


只算回答时：`[−ln0.5−ln0.8−ln0.9]/3≈0.3406`。若六个位置都算，约1.0533。**两个损失的计分集合与分母不同，不能比较谁更小就说哪个模型更强。**

### 4. 两种 mask 要分清

| mask | 限制什么 | 提示是否还可被读？ |
| --- | --- | --- |
| 因果 attention mask | 每个位置不能看到未来 | 回答可读已给提示 |
| loss mask | 哪些目标项进入损失 | 不改变注意力可见范围 |

把提示的 loss mask 设为0，不是删除提示，也不是禁止通过提示路径传梯度。回答预测依赖提示的表示，因此反向传播仍可能更新处理提示的共享参数。

**优化器更新的也不只是输出回答那几行参数。** 如果做全参数 SFT，所有参与计算且可训练的权重都可能得到梯度；如果做 LoRA，仅指定的增量参数可训练。

### 5. 什么是高质量 SFT 数据？

课件列出人工对话、合成指令、数学／代码及安全对齐等类型。数量可从较少样本到大规模指令集，不是越多越好。

要看：回答正确性、事实依据、风格一致性、任务覆盖、提示分布、训练验证隔离、拒答与可回答任务的平衡。

如果大多数样本都以“不能”开头，模型可能学到过度拒答。若只示范超长解释，可能损害需要简短输出的任务。行为异常应先查数据，不要默认再加一阶段训练就能修好。

### 6. SFT、提示工程与 RAG 的区别

- 改系统提示：权重不变，改变当前条件。
- RAG：把检索到的资料送进上下文，权重通常不变。
- SFT：更新权重或适配器，改变模型对输入输出模式的倾向。
- Mid-training：偏向继续学习目标领域或更长序列，名称与边界依训练方案而异。

任务应该用哪种方法，要结合评估、成本与维护，不要求所有应用都微调。

### 理解检查

<details><summary>提示 token 不计损失，是否意味着它的 embedding 永远不更新？</summary><p>不意味着。回答位置可通过注意力依赖提示表示，梯度可能沿这条路径回传。只要该参数可训练，就可能更新。</p></details>
<details><summary>为什么把全文 CE 和回答 CE 的大小拿来排名不合理？</summary><p>它们在不同目标项和不同分母上取平均；提示本身可能更难或更易。要比较模型，必须固定评分集合与数据。</p></details>

## LoRA：用小矩阵学习权重增量

### 1. 为什么不必每次更新全部参数？

PDF 第 53–56 页。基座已经具有许多表示能力，适配任务时不一定需要任意改变整个权重矩阵。LoRA 把**学习的权重增量**限制为低秩结构。

**要纠正一个简化：** 不是把已经训练好的 W₀ 全部压缩成两个小矩阵后丢掉它。常见做法是保留并冻结 W₀，训练新增的 A、B。

### 2. 先说明矩阵约定

本页使用列向量输入，方便与课件 `W=W₀+BA` 对照：

```text
x ∈ R^(d_in)
W₀ ∈ R^(d_out × d_in)
A ∈ R^(r × d_in)
B ∈ R^(d_out × r)
ΔW = s BA，常见 s = α/r
输出 y = W₀x + s B(Ax)
```

r 是秩上限，通常比 d_in、d_out 小。α/r 是常见缩放约定，不是唯一变体；本页手算取 s=1。

<div class="flow"><span class="chip">x</span><span class="arrow">→ 冻结的 W₀ →</span><span class="chip">基础输出</span><span class="arrow">＋</span><span class="chip">x → 小矩阵 A → B → 增量输出</span></div>

### 3. 参数量到底少了多少？

单个4096×4096矩阵，r=8：

```text
全参数矩阵：4096²=16,777,216
LoRA：8×4096+4096×8=65,536
比率：65,536/16,777,216=0.390625%
```

对应这个矩阵需要训练的参数数目约为原来的1/256。**不是整个模型显存直接降为1/256**：基础权重仍要存，前向反向的中间激活也可能很大，其他层、精度和优化器状态都要计算。

### 4. 手算一次 LoRA 前向

取 d_in=d_out=2，r=1：

```text
W₀=[[1,0],[0,1]]，A=[[1,−1]]，B=[[0.2],[0.4]]
BA=[[0.2,−0.2],[0.4,−0.4]]
x=[2,1]ᵀ
W₀x=[2,1]ᵀ
Ax=1，B(Ax)=[0.2,0.4]ᵀ
y=[2.2,1.4]ᵀ
```

基础矩阵没变，增量支路让最终输出变化。

#### 一个容易忽略的细节

这个2×2玩具例子全矩阵4参数，A和B加起来也是4参数，因此**没有节省参数**。它只是便于手算；真正节省依赖 r 远小于维度。不能拿小例子的参数数证明大模型比例。

### 5. 初始化、合并与切换任务

**补充实现直觉：** 常见初始化让一个因子为零、另一个随机，这样初始增量为零，而训练能开始；若两个因子都严格为零，乘积分支的梯度可能一开始都为零。

在兼容条件下可把训练后的 sBA 合并到 W₀用于推理；未合并时可共享基础权重，为不同任务加载不同适配器。并非所有量化、动态路由或服务配置都能无条件合并。

“切换 LoRA”需要知道用户任务对应哪个适配器，模型不因为保存多组 A/B 就自动判断该加载哪组。

### 6. LoRA 应该放在哪些层？

课件先提原论文在注意力投影上的实验，再讨论把 FFN 等线性层也纳入。适配位置、r、数据规模与学习率都影响效果。

不能把“只改 Q/V 永远最好”或“LoRA 与全参效果必然相同”当成结论。参数更少意味着约束更强，是否足够要在任务验证集评估。

### 理解检查

<details><summary>LoRA 是否不需要反向传播？</summary><p>仍需反向传播计算适配器梯度。冻结基础权重只是让它不被更新，不代表模型前向和必要的梯度计算消失。</p></details>
<details><summary>LoRA 是训练阶段还是另一种目标函数？</summary><p>它主要是参数化与更新方式。可以结合 SFT 等目标，不能与“监督微调”当作互斥选项。</p></details>

来源：PDF 第 53–56 页，第 53 页矩阵关系已视觉核对。维度、参数比例和前向例子为教学补充；不依赖具体框架 API。


## 偏好数据：怎样表达“回答 A 比 B 好”？

### 1. 为什么示范好答案还不够？

PDF 第 57–69 页。SFT 教模型模仿示范；偏好数据进一步表达“在同一提示下，两个候选哪个更符合目标”。

比如问：“给我推荐一种和泰迪熊一起做的活动。”

- 回答 A：“可以一起读一本故事书，或者带它拍张主题照片。”
- 回答 B：“别再花时间陪它。”

若目标是友善、有帮助且符合用户要求的回答，标注者可能更偏好 A。这不等于“所有偏好都是事实真伪”，偏好也涉及任务、语气和约束。

### 2. 三种标注形式

| 形式 | 定义 | 例子 | 难点 |
| --- | --- | --- | --- |
| Pointwise | 给单个提示—回答打分 | A=4/5、B=1/5 | 不同人评分尺度可能不同 |
| Pairwise | 同提示比较两个回答 | A 优于 B | 需要处理平局、分歧与比较标准 |
| Listwise | 对多个候选排序 | A>C>B | 排序成本与一致性问题 |

成对比较常比从零写完美答案容易，但并非没有标注成本。不能把采集偏好理解成“不再需要高质量数据”。

### 3. 一条标准偏好对长什么样？

```text
x：提示
 y_w：被偏好的回答（winner）
 y_l：较不偏好的回答（loser）
标签：在 x 和指定评价标准下，y_w ≻ y_l
```

比较应尽量固定提示。拿两个不同难度问题的回答直接判胜负，会把提示差异混进标签；课件示意里的 Observation=(prompt,response)，这里展开成实际训练常用的三元组。

### 4. 候选与标签从哪里来？

<div class="flow"><span class="chip">目标分布中的提示</span><span class="arrow">→ 模型采样／改写 →</span><span class="chip">同提示多个候选</span><span class="arrow">→ 人工或评判器比较 →</span><span class="chip">偏好对</span></div>

候选可以由模型不同采样、其他模型或人工改写得到。标签可以来自人类、任务规则或模型评判，但来源不同应标清。

用模型当裁判可能有长度偏好、位置偏好、风格偏差；BLEU、ROUGE 等相似度指标也不等价于通用人类偏好。人类反馈数据也需要统一 rubric 和复核。

### 5. “负例”不是把错误文字作为目标答案来模仿

普通 SFT 如果直接把坏回答放在目标字段，会教模型模仿它。偏好优化把 winner 与 loser 的**关系**放入目标，形式不一样。

不过 SFT 的 softmax 交叉熵本身也会通过归一化压低非目标候选概率。因此“之前完全没有任何负信号”只能是课堂直觉说法，不能当作数学事实。

### 6. 偏好数据不能修复所有错误

课件第 63 页提醒：模型行为异常也可能是 SFT 数据质量问题。应先检查标签错误、分布不匹配、过度拒答或目标冲突。

偏好训练的评估应包含事实性、帮助性、格式约束与未见任务，而不只看训练集胜率。一个极其礼貌但事实错误的回答并没有因此完成任务。

### 理解检查

<details><summary>为什么一对回答要对应同一个提示？</summary><p>这样比较的差异主要来自候选回答，而不是任务本身不同。奖励模型或 DPO 都需要明确提示条件。</p></details>
<details><summary>AI 生成标签还能直接叫 Human Feedback 吗？</summary><p>应说明标签来源。经典 RLHF 的 HF 来自人类偏好；用 AI 反馈或可验证规则时不要掩盖这种区别。</p></details>

来源：PDF 第 58–69 页及对应字幕；候选内容为教学构造。


## RLHF：先学奖励，再优化回答策略

### 1. RLHF 由哪两步组成？

PDF 第 70–86 页。RLHF = Reinforcement Learning from Human Feedback。经典配方先把人类偏好拟合成奖励模型，再用奖励信号优化生成策略。

<div class="flow"><span class="chip">人类偏好对</span><span class="arrow">→ 训练 →</span><span class="chip">奖励模型 RM</span><span class="arrow">→ 冻结后评价采样 →</span><span class="chip">更新生成模型 Policy</span></div>

**奖励模型与生成模型不是同一个角色。** RM 输出分数，policy 输出 token 概率。两者可能使用相似主干，但训练目标和使用方式不同。

### 2. 奖励模型的输入与输出

```text
输入：(提示 x，完整候选回答 y)
输出：一个实数 rφ(x,y)
```

可以取语言模型某位置的隐藏表示接标量输出层，也可以使用编码器式主干。这个分数不是“事实正确概率”本身，不要求落在0到1，也不是词表分布。

### 3. Bradley–Terry：把分差变成偏好概率

```text
σ(z)=1/(1+exp(−z))
P(y_w ≻ y_l | x)=σ(rφ(x,y_w)−rφ(x,y_l))
L_RM=−E[ln σ(r_w−r_l)]
```

**直觉：** winner 的分数比 loser 越高，模型越相信这个偏好标签，成对负对数损失越低。

例子：r_w=2、r_l=0，分差2，偏好概率约0.8808，损失约0.1269。若两者同分，概率0.5，损失约0.6931。


交互图解（l3-preference-gap）见[对应章节源文档](../../content/collections/cme295/l3-rlhf.md)，构建网站后可在该章节操作。


期望 E 表示对数据中许多偏好对取平均。把所有奖励都加100，分差不变，因此偏好概率不变；没有额外约束时，奖励的绝对零点并不由成对数据唯一决定。

### 4. 为什么奖励不能当真理？

RM 只是在有限标签上学习人的评价规律，可能学到“回答长就更好”“使用某些礼貌词就高分”等捷径。

如果标签本身有分歧、数据覆盖不足，RM 对新任务可能判断错误。验证集应该检查排序质量与各类失效，而不是把训练损失小视为已学到全部价值标准。

### 5. 第二步：优化 policy

policy πθ 通常从 SFT 模型初始化。给它提示，让它采样回答，再用冻结的奖励模型评分。

常见直觉目标（最大化形式）：

```text
J(θ)=E_x E_y~πθ [rφ(x,y)] − β E_x KL(πθ(·|x) || π_ref(·|x))
```

β 控制偏离参考分布的代价。这是说明“高奖励＋不过度偏离”的概念式目标，不是完整 PPO 更新代码。实际还涉及采样、概率比、优势估计、裁剪及可能的 value model，第四讲再深入。

| 对象 | 这一阶段是否更新 | 职责 |
| --- | --- | --- |
| Policy πθ | 是 | 产生更符合目标的回答 |
| Reward model rφ | 经典两阶段中冻结 | 给采样回答评分 |
| Reference π_ref | 通常冻结 | 提供分布约束基准 |
| Value model | 取决于算法 | 估计回报或基线，不是所有方法都有 |

**重要：** 不是把离散生成的字符串直接无条件可导地传过 RM，就能对生成 token 做普通监督反向传播。策略梯度利用 log 概率等构造学习信号，相关细节不能被“评分后反传就行”省略掉。

### 6. KL 在惩罚什么？

KL 衡量两个概率分布差异，并非直接量权重矩阵的欧氏距离。“别改权重太多”是过于粗略的口头直觉。

教学二选一例子：reference=[0.5,0.5]，policy=[0.8,0.2]：

```text
KL=0.8 ln(0.8/0.5)+0.2 ln(0.2/0.5)≈0.1927 nats
```

若两个回答奖励为[1,0]，policy 的期望奖励为0.8；β=0.5 时简化目标 `0.8−0.5×0.1927≈0.7036`。增加奖励需要与偏离代价权衡，不是永远越接近 reference 越好。

### 7. Reward hacking：高分不等于好答案

模型可能找到奖励模型偏爱的形式，却绕过真实任务。例如长篇重复得到高分，但没有回答用户问题。KL 约束能抑制某些过度偏移，**不能保证消除奖励漏洞**。

应配合独立任务评测、人工抽检、奖励数据维护与约束检查。模型越擅长优化错误代理目标，问题可能越明显。

### 理解检查

<details><summary>训练奖励模型与策略优化时，都只更新同一组参数吗？</summary><p>不是。第一步训练 RM；第二步通常固定 RM 与 reference，更新 policy。具体算法可能还训练 value model。</p></details>
<details><summary>把 r_w 和 r_l 同时加10，成对偏好是否改变？</summary><p>不改变，因为 Bradley–Terry 概率只依赖两者分差。这也是为什么不能把绝对分数直接当统一质量刻度。</p></details>

来源：PDF 第 70–86 页，第 76、77、85 页已视觉核对。KL 小例子为教学补充，完整强化学习推导留到第四讲。


## DPO：直接用偏好对训练语言模型

### 1. 为什么要有 DPO？

PDF 第 87–90 页。经典 RLHF 往往要训练 RM，再进行策略优化，工程与调参较复杂。DPO（Direct Preference Optimization）通过重新表达偏好目标，直接在偏好对上优化语言模型，不必单独拟合一个显式奖励模型。

**不是“不需要 reference”**，标准 DPO 仍以冻结参考模型的回答概率作为基准。不是“没有 reward model，所以可以没有偏好标签”。

### 2. 先认识公式里的对象

- x：提示。
- y_w、y_l：同一提示下较好与较差回答。
- πθ(y|x)：待训练 policy 对完整回答的条件概率。
- π_ref(y|x)：冻结参考模型的条件概率。
- β>0：控制目标尺度与参考约束相关性的超参数。

```text
m = β [ln(πθ(y_w|x)/π_ref(y_w|x))
       −ln(πθ(y_l|x)/π_ref(y_l|x))]
L_DPO = −E ln σ(m)
```

课件把 `β ln(πθ/π_ref)` 解释为一种隐式奖励形式，因此成对结构与 Bradley–Terry 相似。

### 3. 一个可手算的概率例子

教学假设完整回答分布中：

| 模型 | winner 概率 | loser 概率 | 其他回答总量 |
| --- | --- | --- | --- |
| reference | 0.2 | 0.2 | 0.6 |
| policy 初始等同 reference | 0.2 | 0.2 | 0.6 |
| policy 更新后的假设状态 | 0.4 | 0.1 | 0.5 |

令β=0.5，初始m=0，损失ln2≈0.6931。

```text
新 winner 概率比=0.4/0.2=2
新 loser 概率比=0.1/0.2=0.5
m=0.5[ln2−ln0.5]=ln2≈0.6931
σ(m)=2/3
新损失=−ln(2/3)≈0.4055
```

我们构造的是“更新后可能状态”，没有声称执行某个优化器一步一定到这组概率。

### 4. 到底鼓励什么变化？

目标鼓励 winner 相对 reference 的 log 概率提升幅度，超过 loser 的相对提升幅度。

**更准确的表述是扩大相对差距**，而非保证“每次 winner 绝对概率都上升、loser 绝对概率都下降”。参数共享和归一化可能使实际变化更复杂。

完整回答概率通常是回答 token 条件概率连乘；实现中用 log 概率求和。不能把某个位置的最高 softmax 值拿来代替整条回答概率，也不能未经说明就改成每 token 平均的变体。

### 5. 与其他方法比较

| 方法 | 训练数据 | 主要目标 | 额外对象 |
| --- | --- | --- | --- |
| SFT | 期望回答 | 提高目标回答 token 似然 | 不必有 reference |
| 奖励建模 | 偏好对 | 学习回答分数排序 | 一个 RM |
| 标准离线 DPO | 固定偏好对 | 扩大相对参考的偏好 log 概率差 | reference |
| 经典 PPO-RLHF | 策略采样＋奖励 | 优化受约束的期望奖励 | RM、reference、常见 value model |

DPO 常以固定离线回答训练，所以也可能遇到与实际模型采样分布不匹配的问题。存在迭代或在线收集偏好变体，不能把所有名字含 DPO 的方法都当成完全相同流程。

### 6. 谁一定更好？

课件第 88 页强调效果依任务和实现，不存在绝对共识。更简单不等于必然更强；强化学习更复杂也不等于必然超越。

评估时固定数据质量、初始化、计算预算和目标任务，检查长度偏好、拒答和其他能力回退，避免仅比较训练 loss 数字。

### 理解检查

<details><summary>DPO 的 winner 与 loser 是训练时重新生成的吗？</summary><p>标准离线 DPO 直接使用固定偏好对；在线或迭代变体可重新收集数据，需要明确采用哪一种。</p></details>
<details><summary>为什么 reference 概率不能直接省掉？</summary><p>标准目标比较的是相对参考的概率变化，省掉就改变目标和约束解释，不再是这里介绍的同一配方。</p></details>

来源：PDF 第 87–90 页，第 87 页公式已视觉核对；概率例子为教学构造。详细等价推导属于后续理论内容。


## 推理训练：可验证奖励与 GRPO 直觉

### 1. 课程里“推理”指什么？

PDF 第 91–124 页使用操作性定义：解决需要计算或组合条件的问题。它与单纯回忆“课程代码是什么”不同，但实际任务常同时需要知识和推理。

第二讲的 CoT 提示试图通过示范分步输出改善结果；本讲讨论用训练提高这类任务表现，而不是每次只在提示里写“请思考”。

### 2. 先建立一个可验证任务

固定规则：Brown 只允许手洗；Panda 可以机洗但不能烘干；Polar 可以机洗和烘干。机洗15分钟，烘干15分钟，30分钟后出门。忽略取放等额外耗时，要求完成**机洗并烘干**。

| 玩偶 | 可机洗 | 可烘干 | 30分钟内满足要求？ |
| --- | --- | --- | --- |
| Brown | 否 | 未给允许 | 否 |
| Panda | 是 | 否 | 否 |
| Polar | 是 | 是 | 是，15+15=30 |

简短可检验说明：“只有 Polar 同时满足两种设备条件，且总时间30分钟。”课堂用例是逻辑约束题，不是通用洗护建议。

### 3. 可验证奖励是什么？

**定义：** 通过明确规则、答案比较或程序测试，对候选输出给出可复查的反馈。例如：

- 年龄算式与固定年份比较。
- 代码通过隐藏测试。
- 输出满足题目明确条件。

**验证也有边界：** 测试覆盖不足、答案解析错误、程序利用测试漏洞，都可能产生高奖励但错误行为。不是“用了程序就不需要检查奖励”。

课件列举 HumanEval、CodeForces、SWE-bench、AIME、GSM8K，代表不同任务；单项 benchmark 不等于所有现实推理能力。

### 4. 输出解释、内部计算与计费别混在一起

模型可能生成用于计算的中间 token，产品也可能只提供摘要。可见解释不一定是内部因果过程的忠实记录，不能凭文字流畅证明推理正确。

课件展示 `<think>…</think>` 是一种格式示例，不是所有 API 都使用同样 token，也不应把要求特定标签当作获得真实内部链路的保证。实际应用更应要求结论、简短理由、引用和独立验证。

推理 token 是否计入预算、上下文和计费，须查服务具体版本。产品界面与年份截图只作为课件快照。

### 5. GRPO 在做什么？

GRPO = Group Relative Policy Optimization。课件第 110–122 页给出直觉流程：

<div class="flow"><span class="chip">同一道题 q</span><span class="arrow">→ policy 采样 G 个回答 →</span><span class="chip">规则或奖励器评分</span><span class="arrow">→ 组内比较 →</span><span class="chip">优势信号＋策略约束 → 更新</span></div>

**优势 Advantage**表达一个候选相对基线好多少。一个常见的教学归一化写法是：`Aᵢ=(rᵢ−组均值)/(组标准差+ε)`。算法变体在是否标准化、序列或 token 级处理上可能不同。

本演示使用总体标准差、忽略非零组的微小ε；方差为0时把优势置0：


交互图解（l3-group-advantage）见[对应章节源文档](../../content/collections/cme295/l3-reasoning.md)，构建网站后可在该章节操作。


奖励[1,1,0,0]，均值0.5，标准差0.5，优势[1,1,−1,−1]。表示前两条相对本组更好；**不是把整条答案逐字直接标为正确与错误**。

### 6. 它不是完整的 GRPO 公式

真实训练还需要处理采样时 policy_old 与训练中 policy 的概率比、裁剪、token 汇总、可能的 reference KL 等。**old policy 与 reference 不一定是同一个角色**：一个记录采样策略，另一个限制相对基准的漂移。

课件配图使用通用“Reward Model”方框，但可验证任务可以用规则或测试直接给奖励，不必训练一个人类偏好 RM。不要仅因为图里写 RM 就认定所有 reasoning RL 都另训奖励模型。

第三讲主要建立直觉；完整目标推导在第四讲继续，不能把本页“优势越高越鼓励”当作可直接运行的更新算法。

### 7. 奖励稀疏的困难

整条答案对或错常只有一个奖励，无法自动告诉每个位置哪一步错。若本组全对或全错，组内相对信号还可能不足。

不是“推理训练只能有最终奖励”：过程监督、工具反馈、其他密集信号和混合目标也是可能方案。这里介绍的是课件集中讨论的结果奖励与组内比较思路。

更长的输出可能在特定实验中出现，但**更长不等于更正确**。要同时观察正确率、token 开销、稳定性与新任务泛化。

## 蒸馏：学生采样，教师提供逐 Token 信号

### 1. 先拆开两个维度

PDF 第 125–131 页。课件对比固定示范上的密集监督与自身采样上的序列奖励，提出希望兼有两者的优势。

| 维度 | 问什么 | 示例 |
| --- | --- | --- |
| 数据分布来源 | 前缀／回答由谁产生？ | 数据集、当前学生、旧策略 |
| 信号密度 | 每个位置有目标，还是整段一个分数？ | token 分布、最终奖励 |

课件将 SFT 称为 off-policy 的直觉对照；严格 RL 中 off-policy 还涉及行为策略与目标策略的关系。不能简单把所有“外部写的文本”都当成完整 RL 定义。

### 2. 蒸馏是什么？

**定义：** 使用教师模型的输出或预测分布作为学生学习目标，把某些行为或能力迁移给学生。教师不必永远更大，可能是专门任务更强、上下文更充分或较早保留某能力的检查点。

- 文本蒸馏：教师生成示范，学生对示范做监督学习。
- 分布蒸馏：教师提供词表分布或 logits，学生在各位置匹配。
- On-policy distillation：在学生自身采样到的前缀上，获得教师信号。

### 3. 为什么要让学生先写？

固定教师示范很干净，却不一定覆盖学生真实会走到的错误前缀。让学生 rollout 后，教师在这些前缀上指导下一步，可以更直接针对学生实际分布。

<div class="flow"><span class="chip">提示 x</span><span class="arrow">→ 学生采样 →</span><span class="chip">学生自己的前缀</span><span class="arrow">→ 教师预测下一词分布 →</span><span class="chip">逐位置比较 → 更新学生</span></div>

与序列级奖励相比，教师分布提供更细粒度信号。不过更细并不自动更真，仍可能复制教师偏差。

### 4. 一个局部的分布比较

在同一前缀上，词表只有“5岁／6岁”两个候选。教学设定：教师p=[0.8,0.2]，学生q=[0.5,0.5]。

```text
软目标交叉熵 H(p,q)=−Σ pᵢ ln qᵢ≈0.6931
教师熵 H(p)=−Σ pᵢ ln pᵢ≈0.5004
KL(p||q)=H(p,q)−H(p)≈0.1927
```

若学生改成q=[0.7,0.3]：软目标交叉熵约0.5261，KL约0.0257。此处“更好”表示更接近给定教师，不是已证明现实事实更正确。

**公式边界：** 这是给定前缀上的 forward-KL／软交叉熵示意，不冒充所有 OPD 的唯一目标。实际方法可能采用 reverse KL、不同采样分布、温度、截断或梯度估计；on-policy 前缀分布本身依赖学生，完整训练推导留待第四讲。

### 5. 教师是否必须提供整个词表？

只有文本答案的 API 不能直接支持完整 logits 蒸馏；只提供部分 logprob 时，也不等价于完整分布。访问能力、费用与数据许可都会影响方法能否实际使用。

更不能把“能看到推理摘要”当作“获得原始内部推理序列”。本课的概念整理不提供绕过服务限制提取隐藏信息的方法。

### 6. 自蒸馏和多教师

- **On-policy self-distillation：** 同一模型的教师分支获得额外答案或更有利的条件，对学生前缀提供监督。教师并不因名称“self”就无需冻结或目标隔离，防止学习目标退化需要具体设计。
- **多教师：** 用不同擅长领域的教师提供信号，可能选择、加权或组合。简单平均冲突意见不保证能力叠加。
- **跨阶段蒸馏：** 用较早 SFT 或 RL 检查点作教师，帮助当前模型保留旧能力，后面的端到端案例会再串起。

这是训练期间迁移，不等于部署时一定同时运行多个教师。

### 7. 两个不能混用的“塌缩／遗忘”

- 模型塌缩：反复用模型生成数据替代原数据，长尾或分布可能逐代退化。
- 灾难性遗忘：继续优化新任务或新目标时，旧能力下降。

蒸馏可能用于保留能力，但不能保证解决所有遗忘；未经筛选的自生成数据反过来也可能带来退化。

## 端到端案例：把训练阶段连成一条线

### 1. 案例怎么使用？

PDF 第 132–164 页以技术报告中的训练流程讨论实际配方。课件使用 GLM-5、其他模型报告与产品快照做例子。

本文整理其**阶段逻辑**，不把未独立核实的模型参数、排行榜、供应商指控或最新数学新闻当成本站事实报道。开放权重也不自动等于完整开放训练代码、数据与许可。

为方便理解，我们构造一个“洗护问答助手”项目，把每个阶段的数据与评价目标写清。它是教学规划，不是真正跑完的大模型训练。

### 2. 阶段一：广泛预训练

任务是学习语言与代码规律，数据可能包含网页、知识文档、代码、数学资料。流程包括清洗、去重、来源分类、质量评估和混合。

对洗护助手而言，基础模型可能知道什么是布料、清洗和时间表达，但尚不一定按请求给出可靠建议。

#### Concatenate and chunk

课件第 139 页把多个文档串成 token 流，再切成固定长度块以提高利用率。文档可能被切开，块首未必恰好是 BOS。

教学示例：已经包括边界标记的文档 A、B、C 分别5、4、3 token，共12；块长8，第一块8、第二块4并补4个 PAD，总槽位16，利用率75%。

```text
文档流：AAAAA BBBB CCC
切块一：AAAAA BBB
切块二：B CCC PAD PAD PAD PAD
```

符号A/B/C代表不同文档的 token，不是每个字母对应真实文字。是否允许跨文档注意力、是否重置位置或使用特殊边界，训练实现需要明确。

### 3. 阶段二：Mid-training 与长上下文

数据改为更贴近目标的长资料：例如产品手册、涉及多个文件的代码修改、含多个约束的文档。目标通常仍是下一 token 预测，但要真正覆盖长距离依赖。

#### Best-fit packing 是什么？

课件第 149 页介绍尽量整份文档装进上下文，不轻易截断，剩余空间必要时填充。

**教学特定算法：best-fit decreasing。** 文档长度先从大到小排序，每次放进“容纳后剩余最小”的已有箱，否则新开箱。这是装箱启发式，不保证全局最优，也不是说报告一定采用本文这一种实现。

```text
长度 [6,5,3,2]，箱容量8
排序 [6,5,3,2]
6 → 箱1 [6]
5 → 箱2 [5]
3 → 箱2 [5,3]（刚好满）
2 → 箱1 [6,2]（刚好满）
最终两箱，总长度16，总槽位16，利用率100%
```

不能只用“省 PAD”判断训练更好，文档完整性、边界、loss mask、位置规则与批次组成都影响效果。

### 4. 阶段三：SFT 学期望回答行为

构造输入：“根据以下标签，哪只熊可以机洗并烘干？”以及正确、简短、有依据的输出。

- 提示包含材料或标签等必要事实。
- 示范回答满足任务格式和条件。
- 常规 response-only loss 只算回答，不把用户问题当待模仿目标。
- 多轮数据需要标注哪些 assistant 回合参与监督；工具调用字段也要按训练模板处理。

课件第 153 页的角色、think 与答案 token 图示说明目标位置，不是要求每个产品公开完整内部思维链。可验证的短解释与最终答案已能用于教学。

### 5. 阶段四：RL 优化可测的任务结果

给模型自己生成回答的机会，再验证：是否选择 Polar？有没有违反“不可烘干”的条件？是否给出可解析的输出？

课件分 reasoning RL、agentic RL、general RL：

| 类别 | 示例信号 | 要小心什么 |
| --- | --- | --- |
| Reasoning RL | 数学／代码任务成功 | 验证器漏洞与题目泄漏 |
| Agentic RL | 在工具环境中完成任务 | 工具副作用、环境可复现、超时 |
| General RL | 指令质量、帮助性等 | 人类／模型评判偏差 |

它们是案例中的训练组织，不意味着所有模型固定按同一顺序三次训练。也不要把“任务奖励提升”当作模型已经会处理所有现实场景。

### 6. 多阶段之后，旧能力还在吗？

**灾难性遗忘**可能发生：某一新任务变好，旧任务变差。例如代码反馈优化后，简洁中文回答或某领域问答下降。

课件第 157–161 页用较早 SFT、reasoning RL 检查点作为教师，为当前学生提供跨阶段蒸馏信号。

<div class="training-stages"><div><strong>早期 SFT 检查点</strong>保留指令行为的教师信号。</div><div><strong>较早 reasoning 检查点</strong>保留已学会的任务能力。</div><div><strong>当前学生</strong>结合新目标与保留信号训练，再用多维评测验证。</div></div>

教师不是永久上线一起回答的多个模型。训练中的保留目标也有成本与冲突，不能保证能力逐阶段只增不减。

### 7. 另一种风险：模型塌缩

课件第 140–143 页强调递归生成数据的长尾丢失与分布偏移。第一代采样遗漏罕见表达，下一代只学这些生成物，可能逐渐丢失多样性与知识。

**不要推成“任何合成数据都有害”。** 经过筛选、验证、与真实资料合理混合的合成数据可以有用；关键是来源多样性、真实任务评价与质量控制。

“现在互联网大部分内容都是 AI 生成”是课件中的动机式表述，本文不提供未经量化的比例判断。

### 8. 怎么验收一个训练方案？

- 用未见样本评估事实正确、约束满足、格式、拒答与语言质量。
- 比较不同阶段的同一套任务，观察增益与遗忘。
- 固定推理配置、模板、模型检查点和工具环境。
- 记录数据来源、去重与验证集隔离，避免训练评测污染。
- 检查时间、显存、token 和标注成本，不只报一个分数。

课件最后讨论模型能力增强可能减少某些 harness 复杂度，但应用仍需工具边界、权限、验证与错误恢复，不能推出“框架与工程从此不重要”。

### 理解检查

<details><summary>模型塌缩与灾难性遗忘是否同义？</summary><p>不同。前者关注递归训练数据使分布与长尾退化，后者关注新目标训练后旧能力下降，可能同时发生但原因和检测方式不同。</p></details>
<details><summary>把所有训练阶段排成一条流水线，是否每个应用都该全部执行？</summary><p>不是。应用者常从现有模型开始，只选需要的提示、检索或适配方式。完整配方用于理解模型训练，不是默认要求从头预训练。</p></details>

## 第三讲复习：数据、目标与更新对象

### 1. 六部分课程主线

| 部分 | 学什么 | 监督信号 | 更新对象 |
| --- | --- | --- | --- |
| Pretraining | 广泛语言与代码模式 | 文本中的真实下一 token | 基础模型参数 |
| SFT | 期望回答与指令行为 | 提示条件下的示范回答 | 全参数或适配器 |
| Preference tuning | 同提示下谁更受偏好 | 偏好对；RM 或直接 DPO 目标 | RM／policy，各阶段不同 |
| Reasoning | 可验证的问题解决表现 | 结果、测试或其他奖励 | policy |
| Distillation | 匹配教师行为／分布 | 文本、logits 或 token 分布 | student |
| Discussion | 组织以上环节并控制退化 | 多任务评价与保留目标 | 由训练阶段决定 |

LoRA 是参数更新方式，不是另一个与 SFT 平行互斥的训练任务。Mid-training 是阶段组织，不能只凭名字推断其唯一目标。

### 2. 一条训练数据，四个问题

读到一个训练方案时，先写清：

1. 输入是什么、目标是什么？
2. 数据由固定语料、当前模型还是教师产生？
3. 损失在 token、回答还是序列上？
4. 哪组参数更新，哪组冻结？

例如“冻结 RM 评价 policy 的样本”不同于“训练 RM”，又不同于“在固定偏好对上做 DPO”。很多混淆来自把这些步骤合成一句“用反馈微调”。

### 3. 快速自测

<details><summary>题1：SFT 的提示 loss mask=0，是不是提示不参与计算？</summary><p>不是。提示仍影响回答表示，可通过回答损失产生梯度。loss mask 和 attention mask 控制不同对象。</p></details>
<details><summary>题2：4096×4096矩阵用r=8的LoRA，训练多少新增参数？</summary><p>A与B合计8×4096+4096×8=65,536，为16,777,216的0.390625%。不意味着全部显存同比减少。</p></details>
<details><summary>题3：RM给winner 102分、loser 100分，是否比2分、0分更有偏好把握？</summary><p>在Bradley–Terry分差模型里相同，两者差都是2，偏好概率约0.8808。</p></details>
<details><summary>题4：标准DPO是不是把winner当SFT样本、丢掉loser？</summary><p>不是。它同时利用两个回答相对reference的log概率差，丢掉loser会改变目标。</p></details>
<details><summary>题5：一组奖励全为1，能直接说policy不需要再训练吗？</summary><p>不能。只能说本组在这种相对优势构造下缺少区分信号，其他题、监督目标和能力仍可能需要改进。</p></details>
<details><summary>题6：学生KL接近教师，是否已经证明事实正确？</summary><p>没有。教师也会错，蒸馏需要独立任务评价，不能只看分布接近。</p></details>
<details><summary>题7：SFT以后为什么还可能有知识截止与幻觉问题？</summary><p>行为适配不等于得到实时、完整、精确的知识库。提示、检索、数据更新和事实核对仍各有作用。</p></details>

### 5. 重要边界回顾

- 预训练不保证知识真实；更多重复数据不保证持续收益。
- Teacher forcing让训练并行，不把推理变成一次生成整句。
- SFT不必更新全部权重；LoRA也仍需要梯度计算。
- 人类／AI偏好标签与可验证正确性是不同来源。
- RM分数不是最终真理，KL约束也不保证免疫reward hacking。
- DPO目标不是“每一步两条答案绝对概率必然一升一降”。
- GRPO的组内优势只是完整目标的一部分。
- 蒸馏目标接近不等于独立任务能力提高。
- 模型塌缩与灾难性遗忘需要分开检测。
